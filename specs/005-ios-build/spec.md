# 功能规范：原生 iOS 构建与签名资源生命周期

**Feature Branch**: `005-ios-current`（当前独立worktree）
**Created**: 2026-10-04
**Status**: 完整实现与必要自动检查就绪／真实 Apple 签名人工待验
**Input**: 基于已验收fee97e8及现有003/004/008/019组件，实现 iOS doctor、可编辑的 archive/export 模板、版本核验与独立签名资源清理；真实用户工程与签名资源尚未指定；2026-10-05用户明确完整代码与必要自动检查先交付，真实签名产物由用户人工验收。

## User Scenarios & Testing

### User Story 1 - 检查并初始化原生 iOS 构建（Priority: P1）
开发者检查本机 iOS 工具与明确提供的签名材料，再生成只构建、收集产物的可编辑配置。
**Why this priority**: 在长时间编译前定位缺少工具、签名材料、过期或不匹配的描述文件。
**Independent Test**: 工具体检返回版本与固定诊断；原生 iOS 初始化产生 ios 命名 build，预览无外部动作。
**Acceptance Scenarios**:
1. 在 macOS 检查当前 Xcode、iOS SDK 与签名身份数量；不输出身份名称、密钥或未知描述文件内容。
2. 显式提供材料时检查文件、描述文件期限、应用/团队绑定以及证书匹配；未提供材料显示待验证，不自动选用宿主身份。
3. 原生单平台初始化生成 ios 命名 build；参数映射、runner 与普通 run/artifact 均可编辑，无审批、上传或通知。
4. 非 macOS 和禁用原生签名支持的构建明确说明未支持，预览及其他 CLI 能力仍可用。

### User Story 2 - 构建版本正确的签名产物（Priority: P1）
开发者用自己明确指定的工程、P12、描述文件与密码引用构建本地 IPA 和调试符号。
**Why this priority**: 交付能核验身份、版本和摘要的本次构建产物。
**Independent Test**: 授权的真实工程生成签名有效 IPA 与压缩 dSYM；归档中版本与显式参数一致。
**Acceptance Scenarios**:
1. 密码不进入进程命令行、脚本、预览、结果或诊断；只导入本次指定 P12，不使用未知宿主私钥。
2. 每次使用独立 DerivedData、archive、export 和收集目录；不把旧 IPA/dSYM 纳入本次快照。
3. 当前 Xcode 支持的导出方式用于本地 export，手动固定证书、团队与描述文件；不自动上传、不注册设备、不下载/创建签名材料。
4. 市场版本及构建版本显式传入，归档产物实际版本、Bundle ID 与预期不符则失败，不给出成功产物结论。

### User Story 3 - 无论结果都清理自有签名资源（Priority: P1）
开发者在成功、失败、取消和收尾失败后保持自己的 keychain、描述文件及其他构建不受影响。
**Why this priority**: 防止临时私钥泄漏、用户资源损坏和并发构建串扰。
**Independent Test**: 真实临时 keychain 创建/导入负例/清理；失败与取消集成检查只清理本次拥有资源，用户 default/search list 不变。
**Acceptance Scenarios**:
1. 系统生命周期负责临时 keychain 与 profile 副本，独立于用户 post/trap；未开始的 build 不准备资源。
2. 部分准备失败也可靠清理；取消及 post 超时不会取消系统清理预算。
3. 不覆盖已有 profile，不删除未知资源，不重写用户 keychain 列表；幂等清理只针对记录的自有资源。
4. 清理失败单独保留证据；原失败/取消原因不覆盖，后续 build 不继续使用未确认清理的签名资源。

### Edge Cases
- 过期 profile、Bundle ID/团队/证书不匹配、错误 P12 密码、缺失引用、空或超限文件。
- CMS 可解码但签名无效；CMS 与固定 Apple 根链及签名用途校验均需通过；自签或非 Apple profile 拒绝，最终签名产物仍需真实 Xcode 导出与核验。
- 路径含空格，profile 安装目标已存在、被替换或变为符号链接；只删除自有且未被替换的副本。
- 取消发生于准备、归档、导出、用户 post；清理自身失败、进程停止未确认。
- 本次输出目录旧文件、伪造版本、硬编码 Info.plist、缺失 dSYM；不得静默成功。
- 单一 app/profile 的模板边界：含 extension 的项目需明确各 target 的 profile 映射，首轮不猜测。

## Requirements

### Functional Requirements
- **FR-001**: iOS doctor 检查 macOS、实际 Xcode/iOS SDK；只给工具版本、身份数量与固定诊断，不扫描未知应用的工程或 profile。
- **FR-002**: 明确材料输入才检查其文件、期限、CMS 签名、固定 Apple 信任锚及 profile 签名用途与应用/团队绑定；未授权身份不可作为构建资源。
- **FR-003**: 原生 iOS 模板使用 ios 命名 build、runner ios/xcode 标签以及既有 run/artifact，不增加步骤类型或独立执行器。
- **FR-004**: P12/profile/password 通过明确引用选择，预览不读取秘密、不准备资源；运行前整个选择批次完成合法性检查。
- **FR-005**: 私钥只导入随机临时 keychain；密码不出现在 OS argv 或输出；只赋予本次签名所需工具访问权限。
- **FR-006**: profile 副本排他安装，不能覆盖已有资源；清理不能删除未知或已被替换的资源。
- **FR-007**: DerivedData/archive/export/输出目录按本次构建隔离，artifact 只收集本次 IPA 和压缩 dSYM。
- **FR-008**: 显式版本/构建号参数合法，归档版本及 Bundle ID 必须与预期一致；不修改源工程的版本文件。
- **FR-009**: ExportOptions 使用当前 Xcode 支持值、manual/export；指定材料/证书，不自动上传、改号、管理开发者账号或设备。
- **FR-010**: 成功、失败、取消、部分准备失败和 post 失败均执行独立系统清理；用户 post 不能替代或跳过该清理。
- **FR-011**: 清理不改用户 default/search list，不杀其他进程；失败记录独立且阻止后续使用，不覆盖原失败/取消。
- **FR-012**: 预览/错误/结果不输出密码、P12/profile 正文；非 macOS 或无原生签名支持明确报未支持。
- **FR-013**: 复用现有受限环境、进程组、预算、日志与快照；签名只由显式配置启用，不从 runner.platform 推断密钥。
- **FR-014**: 缺少用户工程、P12/profile/Bundle ID 等真实资源时，仍完整实现签名校验、资源生命周期及所有消费者，完成必要自动检查与可执行人工验收步骤后可本地提交；真实 Apple 材料兼容、签名 IPA/dSYM 与相应生命周期组合明确记录人工待验，不伪造真实通过。

### Key Entities
- iOS 体检结果：工具、状态、版本、固定诊断和待验证材料。
- 显式签名定义：材料引用、应用标识、导出方式。
- 本次签名资源：临时 keychain、profile 自有副本、构建与输出目录、已导入身份绑定、清理结果。
- 本次产物：签名 IPA、压缩 dSYM、实际版本、003 快照和摘要。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 初始化/预览、缺失工具、非法材料和错误版本均有可运行正反例，原有 CLI 与其他平台不退化。
- **SC-002**: 指定的真实工程生成至少一个版本及 Bundle ID 正确、签名有效的 IPA 与对应压缩 dSYM，摘要可复验。
- **SC-003**: 成功/失败/取消/部分准备失败均无本次签名资源残留，用户资源与无关进程不变。
- **SC-004**: 密码敏感标记不出现于 argv、预览、结果或日志；本次与旧产物隔离。
- **SC-005**: 真实验收条件、已运行命令和人工待验项可追溯；完整实现与必要自动检查可独立提交，工具存在、自签机制和无签名编译不代替真实 Apple 签名验收。

## Assumptions
- 当前移植依赖已验收fee97e8的003/004/008/019组件；远端节点复用同一Run与具体资源函数，不另建执行器。
- 首次模板面向单一 app target/profile；其他 target 不自动猜 profile。用户可编辑模板，但更多 profile 生命周期须明确扩展契约。
- 只使用明示文件/引用；宿主已有身份数量不等于授权。本次允许自产测试材料验证资源机制，不能以其代替 Apple 签名应用。
- 系统清理使用独立有限预算；任意可信 shell 主动逃逸不属于执行沙箱保证，停止未确认单独保留。

## 2026-10-05 验收方式修订

用户明确先完成所有模块实现和必要自动检查，Apple/商店真实材料及上传由用户人工验收，最后统一以Flutter案例验收。本功能不因未提供合法Apple profile/P12停在部分代码；SC-002及依赖合法材料的SC-003/004组合仍需真实用户验证，交付时明确人工待验。材料校验、固定Apple信任锚、密码边界、独立Close、清理不确定闭锁、预算/租约/恢复均不可stub或放宽。没有授权去读取ambient材料。
