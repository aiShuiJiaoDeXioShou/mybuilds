# Feature Specification: 008 重启核对与原快照重试

**Feature Branch**: `008-build-recovery`

**Created**: 2026-10-04

**Status**: 规范完成；007已验收，008实现与应用验收中

**Input**: 用户已授权全部MVP；依据实施路线008与多节点方案，在控制端/节点重启时保留真实执行、预算、收尾和停止保护，支持明确请求原快照的新构建，不自动重跑已开始步骤。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 重启后保留排队与有效执行（Priority: P1）

管理员重启控制端，用户无需重新触发已经排队的构建，仍在有效执行期的节点继续原执行，不产生第二次脚本运行。

**Why this priority**: 重启不能丢任务或制造重复构建。

**Independent Test**: 一个实际任务在运行、一个在排队，停止并重启控制端，在执行权仍有效时核对原任务归属、日志、编号及排队执行次数。

**Acceptance Scenarios**:

1. **Given** 排队任务含原提交、参数和条件事实，**When** 控制端重启且仓库分支已更新，**Then** 排队任务继续使用原快照、原编号和原条件，不重新读取分支。
2. **Given** 节点实际正在执行且执行权未过期，**When** 控制端在有效期内重启，**Then** 不标记中断、不创建替代执行，原节点继续续期与回报；普通与收尾剩余预算均不增加。
3. **Given** 控制端尚不能独占持久状态或恢复校验失败，**When** 尝试启动，**Then** 拒绝调度和写回，不把未知状态重置为待执行。

### User Story 2 - 中断后保留停止保护与已有证据（Priority: P1）

管理员看到原任务中断及停止是否确认；即使控制端或Agent重新启动，也不会静默运行原普通/收尾动作。

**Why this priority**: 中断副作用不可猜测，必须防止旧进程与新任务同时运行。

**Independent Test**: 实际长脚本及收尾过程中断网络/节点进程，重启控制端与Agent，检查旧动作次数、旧回报、保护与管理员独立停止确认。

**Acceptance Scenarios**:

1. **Given** 执行期已到期且原进程停止未知，**When** 控制端启动核对或周期核对，**Then** 记录 interrupted 与停止未确认，保留原归属、失败原因、日志/产物、预算及普通/收尾进度，并保留同名互斥和节点隔离。
2. **Given** 已开始普通或 always 收尾动作后失联，**When** 任一端重启，**Then** 不在原节点或另一节点重跑；迟到回报不能成功结束旧执行，新Agent不能凭旧PID自动发送信号。
3. **Given** 精确旧任务已由当前独立节点身份或管理员提供真实停止证据，**When** 停止确认成功，**Then** 仅解除物理停止保护，旧状态、原失败及证据不改写，也不凭此解除发布结果未知的保护。

### User Story 3 - 显式重试原提交与原配置（Priority: P1）

用户明确重试已结束构建，获得新的构建号和执行，仍能复现首次触发时的提交、配置、参数及条件事实。

**Why this priority**: 用户需要复现失败，不能悄悄改为最新分支或设置。

**Independent Test**: 首次构建完成后修改分支、项目设置和方案；用同一重试请求重复提交并比较原/新快照、编号、关联、实际脚本与产物。

**Acceptance Scenarios**:

1. **Given** 原任务已结束且物理停止明确，**When** 合法用户显式 retry，**Then** 从原快照创建关联原任务的新构建，以当前授权检查但不重新取配置/参数/条件，分配新编号及执行身份，保留原任务不变。
2. **Given** 同一重试请求的网络响应丢失，**When** 相同用户以原请求标识及同样输入再次请求，**Then** 返回同一个新构建，不再增加编号；同标识不同输入明确拒绝。
3. **Given** 原任务停止未知、仍活动、原发布结果未知、当前授权不允许或项目已删除，**When** 请求 retry，**Then** 拒绝且不创建记录、不占新编号、不修改原证据。

### User Story 4 - 查询恢复结果与安全失败（Priority: P1）

用户从原有构建查询和客户端命令得知恢复/重试的关系、归属与失败原因，帮助管理员采取准确动作。

**Why this priority**: 自动化不能把“中断”“等待停止”“新重试”混为一谈。

**Independent Test**: 通过真实客户端和用户身份查询重启/过期/重试记录，校验原构建与新构建关系及安全错误。

**Acceptance Scenarios**:

1. **Given** 构建有原始失败和收尾失败/停止未知证据，**When** 重启后查询原构建与新重试，**Then** 原始证据不被重试覆盖，新记录清楚指向原构建，敏感参数、脚本、凭据与节点私有路径不公开。
2. **Given** retry 来自节点凭据、只读审批者或未授权用户，**When** 发起请求，**Then** 拒绝；本地调试与离线帮助/版本不依赖远程恢复状态。
3. **Given** 原固定提交已被仓库移除或新的执行环境缺少工具/工作区，**When** 新重试执行，**Then** 保留原快照并明确排队/失败，绝不回退新HEAD或伪造原产物。
4. **Given** 中央已确认完整终态但终态响应丢失，本地保留待确认journal，**When** 当前独立节点身份请求核对其精确原执行与最终回执，**Then** 只有中央记录与本地待确认终态内容一致、无未确认物理停止时才清除该条自有journal；原执行权不恢复、不补终态、不自动运行任何动作。缺失/冲突/活动/保护记录保留证据并明确拒绝。

### Edge Cases

- 停止与重试竞争、两个控制端竞争、旧执行权恰好到期、有效续期与启动核对并发。
- 控制端在新重试创建提交后响应前终止，重复请求不能新增任务；编号不能回退或重复。
- 原任务已清理证据、项目已迁组或改名/节点授权变化、条件事实曾为待确定、旧快照损坏。
- 全部条件跳过的原任务、尚未领取、用户取消、原脚本成功但收尾失败、节点本地目录含旧journal。
- 发布/审批由后续功能实现，当前不能通过恢复启用这些能力，也不能设置伪成功/伪等待状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 启动恢复及运行中核对必须遵守唯一控制端持久写权限，权限丢失后不继续授予或写回；启动失败安全退出。
- **FR-002**: 重启必须保留 queued/skipped/所有已结束状态的原身份、编号、快照和条件事实；queued 正常续排，skipped 不自行执行。
- **FR-003**: 尚有效的执行必须保持原节点与完整执行身份，不因重启重新授予或中断；心跳不能代替执行续期。
- **FR-004**: 到期执行核对必须复用真实到期规则，记录 interrupted+停止未确认并保留同名互斥、容量与原节点隔离；不自动迁移或重试。
- **FR-005**: 普通/收尾剩余预算、意图、实际开始、停止/清理结果和真实收尾选择必须持久且重启不重置、不增长；未知已开始动作不得重跑。
- **FR-006**: 节点新进程只能检查旧本地证据，不自动执行或按旧PID杀进程；过期身份不可补成功、日志/产物或动作回报。
- **FR-007**: 物理停止确认必须使用精确旧执行身份及独立当前节点/管理员身份，保留原终态和失败；停止确认不能作为发布结果确认。
- **FR-008**: 显式 retry 必须复用原完整配置、原提交、最终参数与冻结条件事实，不能重新解析当前分支、方案或项目参数，不支持替换这些输入。
- **FR-009**: retry 为新构建而非恢复旧动作，分配新项目构建号及执行身份并关联原构建，保持原任务所有证据不可变；新构建从头使用该定义的完整普通/收尾预算，不能冒充旧剩余预算恢复。
- **FR-010**: retry 仅接受有构建号且已结束的 succeeded/failed/cancelled/interrupted；活动、queued、skipped、停止未确认拒绝。需重新运行 skipped 时另发手动触发。
- **FR-011**: retry 必须重新核对当前项目存在、角色、项目节点范围与发布授权，冻结原允许范围不得扩大为首次未授权节点；当前无合格节点可按原规则排队，不能绕过实际能力检查。
- **FR-012**: retry 必须采用用户明确可重用的请求标识，并原子完成校验、去重与编号分配；响应丢失重发相同内容返回同一记录，同标识不同输入拒绝，不自动更换标识。
- **FR-013**: retry 创建前必须核对原物理停止明确及无发布结果未知保护；检查与创建处于同一持久状态边界，不能并发绕保护。
- **FR-014**: 当前不实现审批/商店/自定义发布的暂停恢复或未知结果解除；恢复不得接受尚未实现能力，后续功能在同一持久边界接入，不建空状态或伪回执。
- **FR-015**: 缺原提交、损坏快照、固定事实不完整必须明确拒绝或安全失败，不改用新HEAD、不重读当前配置、不丢原历史。
- **FR-016**: 用户通过现有构建详情/列表与retry命令查看原/新关系、原失败、普通/收尾/停止证据与状态，公开信息不能泄露配置秘密或节点私有路径。
- **FR-017**: retry 权限沿当前手动触发策略，审批只读与节点凭据不能触发；包含发布定义时要求管理员及明确发布许可，实际尚未实现能力仍按当前执行预检查拒绝。
- **FR-018**: 使用实际控制端重启、节点/真实脚本、网络故障和两种既有持久后端验证相同语义；交叉编译、模拟恢复或只勾任务不能替代验收。完成后执行Spec Kit收敛与整功能本地提交。

- **FR-019**: 必须支持独立当前节点身份核对终态响应丢失的精确已确认回执，安全清除本地待确认终态journal；核对以中央既有完整终态、完整执行归属与原终态内容为依据，不把物理停止确认代替结果确认，不允许旧权限写回或重放。尚未确认的claim/活动/冲突/停止未知不能按此清理，必须明确保留证据。

### Key Entities

- **原构建快照**：首次冻结的提交、定义、最终参数、条件事实与授权范围；不随项目设置变化。
- **执行进度与保护**：节点/执行身份、真实期限、普通与收尾预算、动作意图/开始/停止、停止未确认及证据。
- **重试请求与新构建**：可重用的请求标识、原构建关系、新编号/身份及原快照副本；原构建保持不可变。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 实际控制端在有效执行期内停止并重启，运行中与queued各至少一个任务最终无丢失、无第二次运行，原编号和快照100%保持。
- **SC-002**: 普通和收尾分别至少一次失联/重启，所有旧动作不被自动重跑；有效执行不误中断，到期保护不被绕过，旧回报100%拒绝。
- **SC-003**: 分支、设置与参数更新后实际retry的新执行仍使用原提交/定义/参数/条件，分配一个新编号，原构建证据保持；重复同请求至少20次只产生一个新任务。
- **SC-004**: 所有列明的活动/停止未知/权限/输入冲突/损坏快照负例均拒绝，无新增构建号或记录，无敏感信息公开。
- **SC-005**: 既有两种持久后端运行完全相同恢复/重试用例，真实macOS与Linux节点复验关键恢复路径；完整验收、必要检查与收敛通过后只有一次整功能本地提交。

## Assumptions

- 输入与设计依据：docs/plans/{PLAN,MULTI_NODE,DELIVERY,SPECKIT_ROADMAP}.md；项目原则2.1.0。007已完整验收；008依据已冻结规范继续plan与实现。
- 008不重写007的过期核对/停止API，而补启动/重启闭环和retry实际消费者；一控制端，多独立Agent。
- retry是明确的新完整构建，不是resume；本次沿原定义重新给完整预算，旧构建恢复则严格保留剩余预算。禁止用户替换retry参数，可另手动trigger新提交。
- 允许已停止的成功构建显式重建，跳过/未执行任务使用trigger；所有重复请求由原标识幂等，不添加自动重试策略。
- 未来审批在014接原节点封存恢复，未来发布在010/011/012接未知结果保护；此处不伪造其状态/工作区恢复成功，也不宣布整个MVP已完成。
