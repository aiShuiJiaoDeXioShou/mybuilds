# 功能规范：007 多节点构建闭环

**Feature Branch**: `007-node-agents`
**Created**: 2026-10-04
**Status**: 已实现并验收，Spec Kit收敛无缺口
**Input**: 用户授权的全部MVP目标与多node架构；前置006已验收提交8e1397e。交付独立节点身份、容量与能力调度、固定提交远程执行、租约与停止保护、脱敏日志/产物回传和实际CLI。005保存在独立待验收工作区，不借未验收签名代码。

## User Scenarios & Testing

### User Story 1 - 登记并诊断多个独立节点 (Priority: P1)
管理员创建节点、分配标签与容量，配置节点独立身份连接控制端；能够查看真实平台、工具和健康状态，禁用或撤销节点不能绕过授权。
**Why this priority**: 构建节点应独立鉴权且报告实际能力，不能复用管理员身份或虚构可用工具。
**Independent Test**: 在自有macOS与Linux环境启动实际节点进程，检查身份、平台/能力、重复实例、失联和管理命令。
**Acceptance Scenarios**:
1. 节点身份创建只显示一次，数据库仅存摘要；用户身份与其它节点身份不能操作该节点任务或凭据。
2. 未配置/错误凭据、非法容量或弱权限配置明确失败；节点工具诊断不泄密，不把Linux ARM或macOS系统名当成移动构建能力。
3. 同节点第二实例或数据目录竞争不能重复执行；drain停止领取但允许已有任务续租，disable撤销执行权，有活动或停止未确认任务的节点不能删除。

### User Story 2 - 按授权与容量分配独立命名构建 (Priority: P1)
管理员触发项目后，仅合格健康节点可以领取；同项目同名build保持串行，不同项目或不同build在容量允许时并行。
**Why this priority**: 分布式调度不能扩大项目授权或重复执行同一任务。
**Independent Test**: 两个真实节点竞争领取并执行自有仓库；检查唯一归属、授权交集、容量及串行/并行时间线。
**Acceptance Scenarios**:
1. 同一队列任务双节点竞争只授予一个执行权，分配独立attempt/租约及递增执行代次，领取与容量占用一起持久化。
2. 项目允许节点、平台/标签、真实工具与节点/全局容量取交集；无匹配保持queued并显示原因，无runner只允许默认节点。
3. 同项目同名build跨节点串行，不同build可并行；已开始的任务固定原节点，失联不迁移重跑。

### User Story 3 - 执行固定快照并保存真实进度 (Priority: P1)
节点在独立工作区检出控制端固定提交，按已冻结配置、参数与条件执行；系统上下文和节点密钥严格分离，步骤与预算持久化。
**Why this priority**: 远程执行必须与本地行为一致，并保留可追溯来源及中断事实。
**Independent Test**: 实际固定SHA检出后运行shell、条件、超时与artifact，核对上下文、进度、累计预算和真实Android构建产物。
**Acceptance Scenarios**:
1. 分支/项目设置改变后仍执行原SHA/快照/参数；工作区隔离，Git失败不退到新HEAD或执行其它提交。
2. project/build/node/git/workspace事实可信且不能被参数伪造；只解析声明的节点秘密，不把Agent token、其它步骤密钥或宿主完整环境交给脚本。
3. 每个普通/post动作的启动意图、实际开始/停止、结果和剩余预算有持久化记录；保存失败或失去执行权时不启动后续用户动作，清理不确定保持真实原失败原因。
4. 未实现的生效approval/upload/reports/notifications在整条预检查明确失败，不以空步骤或成功结果代替；005未验收ios_signing不进入本阶段执行。

### User Story 4 - 取消与断网时停止本次执行 (Priority: P1)
管理员发起取消，控制端先保存意图；节点响应停止本次进程组。续租失败或执行权失效时，节点自行保守停止，不能等待网络恢复后继续旧动作。
**Why this priority**: 租约过期只撤销执行许可，不能虚称物理进程已停止。
**Independent Test**: 在普通步骤及always中实际断网/禁用/撤销，包含忽略TERM和后台进程，核查无关进程与停止保护。
**Acceptance Scenarios**:
1. 运行中取消先显示cancel_requested，仅收到进程回收证据才显示cancelled；未执行的队列取消不运行用户post。
2. 失租阻止所有普通和post用户动作并回收本次进程组；迟到续租成功不能复活执行权，无关进程保持运行。
3. 过期/错节点/旧attempt/旧代次回报被拒绝；未确认物理停止保存interrupted与stop_unconfirmed，保留同名互斥并隔离节点。
4. 原节点独立管理身份或管理员凭实际证据确认停止后解除停止保护；不能用过期租约补交执行成功，不解除任何后续商店unknown记录。

### User Story 5 - 查询中央日志与下载已确认产物 (Priority: P1)
管理员或审批身份读取脱敏日志，实时连接断开后继续读取；产物完整回传并核对摘要后可下载，节点离线不影响已确认文件。
**Why this priority**: 中央证据需可靠且独立于可变工作区，后续审批与发布才能复用。
**Independent Test**: 真实日志重发/流重连、缓冲背压、artifact快照分段上传与中央下载，核对权限、字节、大小及摘要。
**Acceptance Scenarios**:
1. 脱敏日志按确定序号/偏移幂等保存，重发不重复，断流可从已确认位置继续；缓冲耗尽明确失败并停止，不能静默丢日志。
2. 文件由受限ID定位，完整大小与SHA256核对后原子可见；坏摘要、短流、越界、旧租约及冲突重发拒绝，部分文件不能下载。
3. CLI日志/详情/中央下载有真实权限检查；节点离线后已确认产物可下载，快照源篡改不改变中央证据。

### Edge Cases
- 两节点同时领取、同node不同session、写事务失锁、时钟偏差和晚到续租；控制端正常重启/Agent崩溃及旧任务本地记录。
- TERM被忽略/子进程后台运行/已退出leader、日志分段秘密与巨大输出、post失租、保存失败/停止未确认。
- Git分支移动/完整SHA不可达/错误凭据、环境引用缺失/路径symlink/FIFO、快照内容被参数伪造。
- 文件传输中断/响应丢失/重复冲突/数据库与原子文件发布间隙、节点离线/已确认源被修改；任意路径或超限消息。


## Requirements

### Functional Requirements
- **FR-001**: 管理员创建/列表/drain/enable/disable/删除节点及撤销/更换独立凭据；只存高熵摘要，一次性显示，不授用户权限。
- **FR-002**: 节点配置校验连接、节点名、凭据、正容量、私有数据/秘密文件、心跳与租约时间；跨主机验证证书，无跳过或泄漏凭据重定向。
- **FR-003**: 节点报告实际OS/架构/工具与本地容量；管理员维护标签/上限/项目授权，节点自报不能取得受保护标签或扩大授权；doctor能解释工具与受限节点状态。
- **FR-004**: 同节点独立session与本地数据目录独占，未确认旧任务不能被新实例忽略；本阶段重启不自动重跑用户动作。
- **FR-005**: 领取以事务同时校验队列状态、项目授权、平台/标签/工具、节点健康、两级容量及同项目同名互斥，保存唯一attempt/lease/递增代次/到期；默认节点规则与无匹配排队一致。
- **FR-006**: 普通节点心跳不隐式续租全部任务；续租须当前节点/session/attempt/lease/代次且尚未过期，撤销/禁用/控制端失锁不授新执行权。
- **FR-007**: 节点从续租请求开始的单调时间计算保守期限，在期限前停止新动作并终止当前进程组；迟到响应不能恢复已经失效的执行权。
- **FR-008**: 所有执行事件、日志、文件与终态回报绑定完整归属及有序幂等序号/内容摘要，条件更新拒绝旧租约、错节点、冲突重复和重复终态。
- **FR-009**: 固定SHA检出节点独立工作区，复用受限Git环境/节点只读凭据，禁宿主hook/helper/默认密钥/任意协议；失败无分支最新回退、不改用户工作树。
- **FR-010**: 执行首次冻结定义/最终参数/条件及可信项目/build/node/git/workspace上下文，步骤模板与when只使用快照；系统事实不可由普通参数覆盖。
- **FR-011**: 远程和本地共用同一流水线执行内核；实际消费者接入逐步进度、剩余预算、独立执行权、日志与产物，不另建executor或未来步骤stub。
- **FR-012**: 节点秘密按声明引用受限加载、逐步注入且日志脱敏，不全局修改环境；Agent token/控制端凭据/其它任务秘密不交给脚本或公共响应。
- **FR-013**: 动作前保存启动意图并校验有效执行权，动作后保存实际Started/进程回收/结果/耗时及剩余普通与post预算；保存失败不继续动作，不以显示毫秒反算预算，不重置累计预算。
- **FR-014**: 普通失败保留原因，post按既有成功/失败/always语义执行且有独立累计预算；有效用户取消可执行既定always，失租禁止所有用户post，系统回收不依赖用户脚本。
- **FR-015**: 取消先持久化；queued取消不运行post；运行中收到真实停止和清理证据前保持待确认，不把发出TERM或租约过期当成成功停止。
- **FR-016**: 过期/无法确认停止保存interrupted+stop_unconfirmed、同名互斥、原节点隔离和禁止删除；已开始任务不自动迁移，显式retry和完整恢复在008接入。
- **FR-017**: 原节点独立管理身份或管理员实际证据可确认原attempt停止，不能恢复旧结果提交权，不能解除后续外部发布unknown锁；有保护的节点不得删除。
- **FR-018**: drain仅停止领取、已有执行继续续租；disable/凭据撤销撤销执行权并等待停止/到期；enable不跳过停止保护，删除须无活动/等待/保护记录。
- **FR-019**: 脱敏日志先有界持久缓冲再按序号/偏移回传，确认后释放；重复相同内容幂等、冲突拒绝；背压或缓冲耗尽明确停止，不静默丢失。
- **FR-020**: 中央日志及历史/实时读取保留UTC/build/步骤/流事实，断连续读不重复；流超时独立于普通请求预算，取消关闭连接，admin/approver可读、trigger/node身份不能越权读取。
- **FR-021**: 产物仅来自独立快照，受限中央ID和普通路径，流式大小/SHA校验、临时文件原子发布与完成记录后可见；提交前复核租约，响应丢失可同ID幂等查询/重发、不覆盖冲突。
- **FR-022**: 中央下载对已确认产物鉴权并保留原大小/SHA；节点离线后仍可用，部分文件/路径攻击/坏内容失败不成为可信证据。
- **FR-023**: CLI接入真实Agent serve/doctor/help/version、节点管理、远程doctor/logs/download/cancel与安全build/status证据；Agent本地doctor/help/version无需控制端连接或token，未知/未实现选项明确拒绝，不挂空能力。
- **FR-024**: 生效approval/upload/reports/notifications及未验收ios_signing在整条执行前检查明确失败；后续008/009/010/011/012/014/015/019/020仍独立验收，不将通用macOS执行冒充签名支持。
- **FR-025**: 两数据库使用同样节点/租约/并发/条件更新/取消/保护/分页验收，控制端重启保留有效租约不误判全部中断；本阶段只安全核对，完整恢复另属008。
- **FR-026**: 实际macOS与Linux节点执行固定SHA shell/artifact闭环及双节点并行/串行、断网、停止、日志/产物验收；真实Android工程另核对远程版本/签名/快照与取消，交叉编译不算真实工具能力。
- **FR-027**: 全部外部配置/消息/文件/分页/缓冲/事件/超时有界，安全响应与日志不公开快照/密钥/底层错误，不接受任意服务端或节点路径。
- **FR-028**: Spec Kit规范/规划/任务/真实验证与README/历史同步；全量/vet/race/必要双库与实际二进制检查、converge无缺口后整功能一次本地提交，无push；005及全MVP真实门保持。

### Key Entities
- 节点：独立身份、管理员标签/上限、实际能力/session/心跳、禁用与停止保护。
- 执行权：build归属、attempt、租约标识/代次/到期及取消意图。
- 执行证据：冻结快照、可信事实、普通/post步骤、实际开始/回收与剩余预算。
- 中央日志与产物：有序确认位置、内容摘要、完整记录与受限下载身份。
- 停止确认：原attempt、执行者、UTC与真实证据，独立于执行成功和商店结果。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 两个独立真实节点完成同一控制端的领取/执行/查询，竞争一任务只执行一次；相同名称串行、不同名称在容量允许时出现真实并行。
- **SC-002**: 无匹配/未授权/工具缺失保持排队，错身份/session/attempt/代次/过期回报与重复冲突全部拒绝；两种数据库的状态与约束结果一致。
- **SC-003**: 固定提交与参数改变后首次快照仍可核对；普通/post步骤与预算逐次留证，保存失败不启动下一动作，实际Android远程产物版本和签名正确。
- **SC-004**: 实际断网/撤销/取消覆盖普通步骤与always，回收本次前后台进程且无关进程存活；未确认停止持续互斥，旧执行权不复活，不自动迁移。
- **SC-005**: 日志重发/断流续读结果完整且不重复，背压明确失败；中央产物下载字节/大小/摘要一致，节点离线仍可下载，损坏/短流/越界/冲突不能成为证据。
- **SC-006**: 实际CLI完成节点管理、诊断、触发、日志、取消及下载；全部安全负例与必要检查通过，当前未实现步骤明确失败，005签名和全MVP门不被降低。
- **SC-007**: 全部功能任务与收敛缺口闭合，规范/文档/验证及整功能提交可追溯；控制端仍不执行仓库脚本，节点没有用户管理权限。

## Assumptions
- 沿用单控制端及可信管理员登记仓库，不实现多控制端HA、逐步跨节点迁移或自动重试已开始动作。
- 已有自有macOS与Linux ARM环境、真实Android工程/工具；Linux ARM仅验通用协议，不以系统名宣称Android工具可执行。全MVP实际Linux Android仍保留原真实门。
- 005待真实Apple材料验收，其48文件独立保留；后续验收集成后补签名资源与租约取消联验，007当前不借签名代码或声称IPA能力。
- 默认容量/全局并发1、心跳5s/租约30s，正式时序与消息上限在plan/contracts冻结；可测试配置必须保持保守执行期限。
- 生效暂未实现功能失败清晰；列为未来需求不能使当前任务静默成功。缺失真实材料按原MVP记录保留，不虚构证据。
