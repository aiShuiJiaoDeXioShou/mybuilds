# Feature Specification：App Store 上传、显式提交与未知结果核对

**Feature Branch**：`011-app-store-planning`
**Created**：2026-10-05
**Status**：规范草案；实现与验收须等待008、009、019及真实Apple签名条件。
**Input**：按用户确认的完整MVP，支持原生/Flutter iOS向App Store Connect上传真实签名IPA、显式提交App Review，并区分上传、审核和正式发布；通过第三方工具完成，失联结果不自动重发。

## User Scenarios & Testing

### User Story 1 - 上传原固定签名IPA（Priority: P1）

管理员把已准备的Apple应用绑定项目，选择具备Xcode、分发签名和商店授权的macOS节点；构建通过后上传本次唯一IPA并查看App Store Connect实际构建。

**Why this priority**：提供主要iOS渠道的完整分发闭环。
**Independent Test**：实际签名产出IPA并上传已准备应用，核对远端应用、版本和构建号。

**Acceptance Scenarios**：

1. **Given** 有效应用与授权、唯一签名IPA和通过的声明测试，**When** 管理员发起默认发布，**Then** 仅上传本次原IPA，不提交审核、不自动正式上架，保存原意图、摘要、报告与远端可核对构建。
2. **Given** 原生或Flutter iOS构建，**When** 选中一个命名build发布，**Then** 共用同一平台分发与签名核验，不能改用另一build的IPA。
3. **Given** 未签名、签名不匹配、多IPA、错误应用/版本/构建号或收集后改变，**When** 请求上传，**Then** 外部上传前拒绝，不重新构建或改签名替换原产物。
4. **Given** 缺商店授权、签名、工具、应用记录或接入前提，**When** 诊断/发布，**Then** 明确缺失项；不读取个人账户补齐、不交互登录、不自动接受协议。

### User Story 2 - 显式提交App Review与选择正式发布（Priority: P1）

管理员在本次上传步骤明确选择是否提交审核、审核通过后是否自动正式发布。提交沿同一构建的原执行权限和累计预算进行；任务结束后只查询原结果，不另启提交动作。系统区分仅上传、可提交、已提交和已发布，缺前提不能伪报提交成功。

**Why this priority**：MVP需App Store发布路径，不能只上传测试构建。
**Independent Test**：在具备发布前提的实际应用验证显式提交审核路径；默认与非管理员路径不得提交或自动发布，不等待外部审核通过。

**Acceptance Scenarios**：

1. **Given** 用户未指定提交与自动发布，**When** 默认发布或原快照重试，**Then** 两者均false；工具退出0不推断已提交或正式发布。
2. **Given** 本次upload已明确选择提交且原远端构建处理完、元数据/权限等前提完整，**When** 同一构建仍有有效执行权和剩余预算，**Then** 提交该远端版本并保留精确意图与回执，不再次上传或替换IPA。
3. **Given** 构建尚处理、元数据缺失、权限不足或自动发布未明确授权，**When** 提交/发布，**Then** 明确前提错误，不擅自补素材/声明、不扩大公开发布。
4. **Given** 非管理员或没有明确上传许可，**When** 触发、retry或显式提交，**Then** 拒绝；条件跳过审批不能代替批准。

### User Story 3 - 共用应用保护并核对未知动作（Priority: P1）

同一Apple应用唯一绑定项目，所有build与节点共用发布保护。上传或提交可能发生但结果不明时，管理员核对精确原动作，不靠进程停止重发。

**Why this priority**：避免重复副作用和跨项目版本冲突。
**Independent Test**：20同应用竞争只一次授权；实际上传/提交后丢回执，重启持续unknown，查询/人工精确确认不再次发送。

**Acceptance Scenarios**：

1. **Given** 应用已核验绑定A，**When** B绑定同应用或A各build/节点20个申请竞争，**Then** 跨项目拒绝，同应用至多一个获得动作执行权，持久化意图失败不启动外部动作。
2. **Given** 同应用远端版本已冲突，**When** 请求发布，**Then** 拒绝，不覆盖、不改号、不自动重建。
3. **Given** 已授予上传或提交执行权，**When** 启动前后失联或缺可信回执，**Then** 对精确原动作默认unknown，保持应用保护；未报告启动不证明未发送。
4. **Given** unknown原动作，**When** 重启、retry、重复请求、取消或确认进程已停止，**Then** 不自动重新上传/提交，停止确认不解除应用保护。
5. **Given** 原应用/版本/构建与动作意图，**When** 管理员显式查询取得充分关联证据，**Then** 更新精确原动作与审计；查询失败、无匹配或仅发现上传构建但未证明提交结果，原提交仍unknown。
6. **Given** 查询不足，**When** 管理员有依据地确认精确原动作，**Then** 保存身份/时间/依据/结果，相同决定幂等，错归属/冲突/仅进程状态拒绝；仅确证未发送或远端明确拒绝才failed并解除保护。

### User Story 4 - 查看真实状态和安全证据（Priority: P2）

用户查看脱敏关联记录并显式查询后续处理/审核状态；上传结束节点继续构建，不等待审核。凭据与签名材料保持受限。

**Why this priority**：用户需要可信可追溯状态，而不是工具退出码。
**Independent Test**：真实查询对应构建和审核状态；扫描公开输出和权限负例，检查节点后续任务。

**Acceptance Scenarios**：

1. **Given** 上传完成而商店仍处理/审核，**When** 查看与查询，**Then** 展示已证实的uploaded/processing/submitted等状态，不声称published，不长期占用节点槽，不再次上传/提交。
2. **Given** 测试机密或工具错误，**When** 查看列表/详情/日志/错误，**Then** 不出现机密、完整脚本、私有路径或完整环境；未授权身份无法读取或修改。
3. **Given** unknown或有效原发布证据，**When** 普通保留清理、项目改组或后续retry，**Then** 不能删除unknown保护所需证据，不能改变原应用归属、原产物/报告或原意图。

### Edge Cases

- 同应用的上传、审核提交、后续查询是不同动作，上传存在不能证明提交成功。
- 单次多副作用流程中前动作已成功、后动作未知；保持动作级原证据，不一概失败并重发全部。
- 商店已有构建号/版本与外部发布冲突；远端查询零结果、多个候选、权限变化。
- 构建取消、预算耗尽或租约过期而远端仍处理：保存已确认uploaded与尚未授予提交权的事实，不重发上传；终态后的查询不启动提交，旧完整身份回报拒绝。
- IPA链接/替换/多匹配、包标识/版本签名不符、声明测试缺失/失败/封存后改变。
- 处理中的构建或不完整发布元数据；审核拒绝不等于上传没有发生。
- 重复/冲突决定、查询与人工确认竞态、应用保护跨重启、未知记录保留。
- 本地有效upload在任何脚本前拒绝，dry-run不访问商店/读取密钥；TestFlight不替代本功能的App Store提交路径。

## Requirements

### Functional Requirements

- **FR-001**：管理员可上传唯一已收集签名IPA至已准备的App Store Connect应用，默认只上传，不提交审核或自动正式发布。
- **FR-002**：原生与Flutter iOS产物共用同一平台分发和安全规则；仅具备实际工具、签名与授权能力的macOS节点执行。
- **FR-003**：诊断实际工具版本、受限商店授权、应用与签名前提；缺失明确失败，不读取个人材料、交互登录、自动接受协议或更新工具。
- **FR-004**：商店/签名机密只用授权节点受限材料引用，不放明文参数、中央快照/记录、日志、公开输出或错误，不继承完整环境。
- **FR-005**：动作前核对唯一IPA文件边界、摘要、包结构、应用、版本、构建号及分发签名；错误/多匹配/改变拒绝。
- **FR-006**：绑定原build、提交/配置/参数、构建号、完整节点执行身份、产物与声明测试封存证据，不重新构建、改签名或用另一产物替换。
- **FR-007**：声明测试须通过并封存才发布；缺失/失败/错误/之后改变拒绝，未声明不伪造通过。
- **FR-008**：submit_for_review与automatic_release默认false；管理员明确选择才生效，恢复/重试/查询不得扩大原授权。
- **FR-009**：支持在本次upload明确选择提交原远端构建至App Review，核验处理状态、权限和已准备元数据等前提；同一构建原预算内有界等待处理，超预算保已确认上传和未执行提交事实，不重传或在终态后复活提交；缺前提明确失败，不补素材/隐私声明或代接受协议。
- **FR-010**：审核提交与自动正式发布分别授权并记录，自动发布必须以明确提交及发布许可为前提，不能仅上传工具成功就放行。
- **FR-011**：含上传定义的触发与retry保持管理员和明确上传许可；显式提交/确认须管理员，条件跳过审批不视为批准。
- **FR-012**：已核验商店应用唯一绑定项目，跨项目绑定拒绝；各build/节点共用应用保护，改组不改变归属。
- **FR-013**：每次不可逆动作先持久化原意图与应用保护再授执行权，20个同应用申请至多一次授权；持久化失败不得执行。
- **FR-014**：远端版本/构建号冲突拒绝，不覆盖、暗改计数或重建产物。
- **FR-015**：上传/提交在普通构建和测试后，受原累计预算、租约、取消与授权约束；旧完整身份不能启动新动作或取得发布权。
- **FR-016**：每个授权绑定一次具体动作，应用层不自动重跑完整发布；接入须核实第三方工具不会在未知副作用后非幂等重发上传/提交。
- **FR-017**：已授权但缺可信终态回执默认unknown，包括启动前后失联；保护跨重启保持，不迁移、不重放。
- **FR-018**：分别记录上传与提交原意图/结果；前动作确认成功不能替代后动作回执，后动作未知不允许重跑前动作。
- **FR-019**：unknown阻止同应用后续发布；retry、取消、停止确认和退出码不解除保护，审核拒绝不证明原上传没有发生。
- **FR-020**：只有可信证据确证该动作未发送或远端明确拒绝才failed并解除其保护，普通连接/超时/进程非零不足。
- **FR-021**：管理员可按原应用、版本、构建及动作显式查询，查询不上传/提交；无充分证据仍unknown，不占构建槽。
- **FR-022**：管理员可有依据地确认精确原动作，保存身份/时间/依据/结果，拒绝错归属/冲突/仅停止证据，相同重复决定幂等。
- **FR-023**：区分uploaded、processing、submitted、published、failed、unknown及远端标识，仅显示证实状态，不以退出0证明提交或正式上架。
- **FR-024**：动作结束释放节点构建槽，不等待商店处理/审核；后续显式查询不能自动重新上传/提交。
- **FR-025**：客户端列表/详情/显式查询/确认提供同一脱敏表格/JSON，沿现有角色鉴权，unknown与关联原产物/报告/关系受后续保留保护。
- **FR-026**：本地有效upload在任何脚本前拒绝；dry-run不读取节点机密、不访问商店。
- **FR-027**：与008恢复、009框架/节点、019报告和010共同发布规则集成，保持原构建与证据行为；014审批及020保留后续真实联验，不绕过未实现审批。
- **FR-028**：验收包括实际签名IPA、App Store Connect真实构建、显式App Review路径、默认不提交/发布、20并发、错材料/应用/版本、丢回执/重启unknown、查询/确认与必要检查。缺真实材料须待验证，模拟结果不能算完成；不等待外部审核通过。

### Key Entities

- **Apple应用绑定**：唯一项目归属、核验应用标识与发布授权。
- **发布动作意图**：上传或审核提交的原动作、原构建/执行归属、应用/版本/构建号、IPA与报告证据、明确发布选择。
- **应用保护**：同应用活动/未知动作占用，不随节点槽释放解除。
- **动作回执**：该动作已证实状态、远端标识和原证据，不是另一动作结果或退出码。
- **核对审计**：显式查询/人工确认的原动作、身份、时间、依据、决定与重复/冲突结果。

## Success Criteria

### Measurable Outcomes

- **SC-001**：实际原生及Flutter签名IPA各一次进入已准备应用，远端应用/版本/构建号可核对，默认不提交审核或正式发布。
- **SC-002**：实际应用的明确App Review提交路径有可核对结果；缺前提/非管理员/默认不提交与不自动公开的负例全部正确，不以审核通过等待时间验收。
- **SC-003**：错误包/应用/版本/签名/摘要、多产物、声明测试失败/缺失/改变、过期权与无授权全部在外部动作前拒绝。
- **SC-004**：20同应用并发至多一次授权，重复请求/恢复不会第二次执行同动作；上传结果不能错误确认未知提交。
- **SC-005**：实际动作丢回执后unknown及应用保护持续跨重启/停止确认，只有充分查询或有依据的精确确认才更新，原证据保持。
- **SC-006**：公开输出不出现注入机密，各读取/修改权限与授权一致，unknown证据不因清理删除。
- **SC-007**：动作结束后下一排队任务能执行，不等待处理/审核；后续查询不重新上传/提交、不声称未经证实published。
- **SC-008**：所有验收有真实证据，必要检查与收敛无阻塞；缺材料明确待真实验证，不能宣称完整MVP完成。

## Assumptions

- 依据BUILD_DISTRIBUTION.md、MVP_EXECUTION.md。本次仅规范预备；原008/009/019依赖及005真实签名门保持。
- 用户准备Apple账号/协议、应用记录、分发签名、API key授权、版本元数据与隐私声明，系统不读取个人账户补齐、不生成素材或自动接受协议。
- 用户要求第三方成熟工具；具体锁定版本、内部重试与协议细节由plan核实，规范不虚构版本和通过结果。
- 实际验证以已授权测试应用上传/显式提交路径为范围，公开自动发布不是默认测试副作用；审核结果由外部决定。MVP显式提交来自upload中的选择，不新增任务结束后的独立提交命令/执行生命周期；终态后只查询与精确原结果确认。
- 010/011共享应用保护与状态核对语义，不共享商店机密；实际共享代码以两个真实消费者为依据。
- TestFlight与额外分发、商店素材/账号管理不在本功能；可信仓库普通脚本自行发布不获得内置核对保证。
