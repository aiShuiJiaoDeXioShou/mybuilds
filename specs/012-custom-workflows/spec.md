# Feature Specification: 可复用构建方案与用户自定义发布

**Feature Branch**: `012-build-presets-planning`
**Created**: 2026-10-05
**Status**: 规范冻结；进入代码与必要自动验证，真实签名及商店上传由用户最终统一人工验收
**Input**: 用户要求沿既定012范围复用现有配置、预览、执行、快照与发布边界，支持没有仓库配置的命名方案绑定、强制来源及custom发布，不增加另一套执行器。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 没有仓库配置也能明确选择构建（Priority: P1）

管理员为可信仓库登记框架与平台，用户分别选择Android或iOS构建，不必先往仓库加入流水线文件。

**Why this priority**: 让现有应用复用一致方案，并保持项目授权与命名构建的既有语义。
**Independent Test**: 使用无流水线文件的真实仓库登记单平台、双平台项目，选择一个或两个构建，检查实际执行、版本及各自产物。
**Acceptance Scenarios**:
1. **Given** 无流水线文件且明确native或flutter及目标平台，**When** 初始化项目，**Then** 绑定对应android/ios命名构建，不修改仓库、不猜测工程或材料。
2. **Given** 同仓库绑定双平台，**When** 用户明确选择一个或全部构建，**Then** 所选使用同一提交、独立身份和不同项目构建号，分别匹配合法节点，失败不取消另一构建。
3. **Given** 多个构建且未明确选择，或未知/重复平台、缺框架配套参数，**When** 注册或触发，**Then** 明确拒绝，不能默认挑一项或部分登记。
4. **Given** 旧default流水线或自定义模板，**When** 使用旧命令或生成本地配置，**Then** 名称与原行为保留，本地执行不读取控制端方案。

### User Story 2 - 仓库定义与方案来源可预测（Priority: P1）

管理员维护可复用单构建方案，项目可以选择默认优先仓库、强制仓库或强制方案，用户知道最终使用哪份定义。

**Why this priority**: 错误配置不能悄悄变成另一条构建或发布流程。
**Independent Test**: 对同一固定提交分别准备合法文件、确实缺失文件、损坏文件，触发三种来源并核对完整定义与来源证据。
**Acceptance Scenarios**:
1. **Given** auto且仓库文件存在，**When** 触发，**Then** 仅使用仓库完整集合；有绑定也不合并构建或步骤。
2. **Given** auto且固定提交的文件确实缺失，**When** 有明确方案绑定，**Then** 仅展开绑定集合；没有绑定则报错。
3. **Given** 文件存在但非法、越界、无法读取，或获取提交失败，**When** auto触发，**Then** 拒绝且无回退、无部分入队。
4. **Given** repo或profile强制来源，**When** 触发，**Then** repo缺失报错；profile忽略仓库配置但仍固定真实提交，不因仓库存在改换来源。
5. **Given** 自定义方案包含多个构建、嵌套方案、相互冲突定义或无法安全读取的文件，**When** 管理员加载或项目引用，**Then** 明确拒绝，不执行文件、不下载远端模板。

### User Story 3 - 参数覆盖与重试保留原始事实（Priority: P1）

用户以声明参数调整版本、渠道与脚本输入，构建展开后不受方案编辑或项目设置变化影响。

**Why this priority**: 可复用配置仍须可追溯并重现原构建，不能扩大权限。
**Independent Test**: 用不同项目默认和命名触发参数构建后修改方案、绑定与分支，重试检查原提交、完整定义、最终参数、条件及产物。
**Acceptance Scenarios**:
1. **Given** 流水线默认、项目命名默认及共享/命名触发参数同时存在，**When** 触发，**Then** 按既定优先级解析并完整校验；未知、未声明、缺required或choices错误即使when不满足也整批拒绝。
2. **Given** 同方案绑定不同名称或项目，**When** 并发触发，**Then** 各自名称、编号、版本和授权独立，不修改方案或别人的定义，缺系统事实不被当成when失败。
3. **Given** 构建已入队后方案/模板/绑定/分支被改，**When** 执行或显式原快照retry，**Then** 仍用原提交、定义、参数、条件和来源摘要；新执行有新号，旧证据不变。
4. **Given** 方案声明超出项目节点范围或含上传，**When** 无当前权限的用户触发，**Then** 权限先于when判断，拒绝且不占号，不靠方案绕过授权或能力检查。

### User Story 4 - 自定义发布使用同一安全边界（Priority: P1）

授权用户可用可信仓库命令调用已有渠道或Fastfile，系统记录原产物、发布意图与可核对结果，失联不会重复发布。

**Why this priority**: 用户扩展需要与内置渠道同等的授权、取消与结果未知保护。
**Independent Test**: 使用自有接收端及真实命令，验证一次授权、原产物、结果文件、丢响应与查询/人工确认；不发布用户商店应用。
**Acceptance Scenarios**:
1. **Given** 已验证应用绑定、唯一原产物和必要测试放行证据，**When** admin明确允许custom上传，**Then** 命令在可信工作区及有效执行权内按原参数数组运行，秘密不进入公开命令或记录。
2. **Given** 命令退出成功但无有效结果，或授权后失联/取消/结果冲突，**When** 回报或恢复，**Then** 结果unknown并保应用保护；停止确认不证明发布结果，禁止自动重发。
3. **Given** 有合法结构化回执或明确无副作用证据，**When** 中央核对原意图、产物与权限，**Then** 记录实际动作及远端状态，不把退出成功当成公开上架；并发同应用不能绕锁。
4. **Given** 可选只读查询能力或仅人工依据，**When** 管理员显式核对unknown，**Then** 沿当前独立身份记录充分证据，不授第二次上传；空结果或进程停止不能解除保护，没有查询能力也不自动重试。
5. **Given** 本地run、失权、测试未通过、审批尚未放行或错误凭据/产物/输出路径，**When** 请求实际发布，**Then** 在副作用前拒绝，原Reason与独立收尾/清理边界保持。

### Edge Cases

- 固定提交存在目录、symlink/gitlink或非法配置路径，与真正缺失不可混同；读取失败不能回退。
- auto与profile切换后default/android/ios名称不相同，旧选择、命名参数及后续自动触发范围须显式修改，不自动映射。
- 项目组变更不继承方案、不改授权/编号；旧pipeline.profile/params作为default简写与builds互斥。
- 同请求响应丢失、并发方案编辑、批次部分校验失败，不得产生另一配置、部分构建或重复发布。
- 本地模板、方案和custom结果出现FIFO、symlink、硬链接、越界、超大、重复/未知/null字段、坏编码或秘密，必须有限拒绝且不回显正文。
- custom内部外部行为无法自动识别；普通run自行发布不享有结果保证，custom查询声明只读不能由系统证明任意用户脚本无外部副作用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 支持四种既定内置构建方案native-android/native-ios/flutter-android/flutter-ios，直接绑定无需注册同名方案；框架与平台不自动推断发布渠道。
- **FR-002**: 管理员可明确加载自定义名称的完整单构建方案，内置引用或本地文件二选一；不接受多构建、嵌套继承、步骤合并、远端模板或动态插件。
- **FR-003**: project init/add可按framework与platform单/双平台绑定android/ios；不写仓库或创建工程、签名、SDK，非法或冲突输入整项拒绝。
- **FR-004**: source采用auto/repo/profile既定规则；auto仅在固定提交配置确实缺失时回退，repo强制存在，profile只用绑定集合。
- **FR-005**: 文件损坏、非法路径/权限/格式、非普通文件、获取提交失败不是缺失，不能回退或部分入队。
- **FR-006**: 仓库和方案构建集合整体二选一，不合并名称或步骤；原根流水线仍default，不自动映射来源切换后的不同名称。
- **FR-007**: 多命名构建沿现有显式选择、共享项目计数器、独立身份/节点/工作区/日志/产物与同名互斥，固定一个批次提交，失败不取消其它构建。
- **FR-008**: 项目设置导入与框架/平台/file输入冲突须拒绝；更新只替换明确提供的顶层块，不改变原项目/计数器/已入队任务；组不增加继承层。
- **FR-009**: 参数仅覆盖所选定义声明项，优先级为命名触发>共享触发>项目命名默认>选定定义默认；兼容default旧profile/params且与builds互斥。
- **FR-010**: 先校验所有所选参数/模板/权限，再判断when；required/choices及未知或未选择scope整批拒绝，不把编号/节点等待确定事实当成build条件失败。
- **FR-011**: 方案不能扩大节点范围、项目发布权限或通知策略；含upload无论when结果均需admin和明确允许，实际能力仍按原预检查及节点匹配。
- **FR-012**: 执行前保存原固定提交、最终完整定义、参数、条件、实际来源名称/路径及内容/模板摘要；入队后编辑不改变任务，retry沿原快照且产生全新证据。
- **FR-013**: 内置和自定义方案与本地模板共用配置及执行语义，版本参数与可信构建号、节点标签、签名生命周期和产物验证沿各平台既定能力；未验收平台不冒报支持。
- **FR-014**: 本地init可读取明确本地模板并严格校验、拒覆盖；本地run继续要求明确仓库文件，不连接控制端取方案，生效upload在任何本地动作前拒绝。
- **FR-015**: 方案/模板/参数/来源错误公开仅安全原因，预览和详情不显示普通参数值、脚本、凭据或控制端/节点私有路径，不解析预览秘密。
- **FR-016**: custom发布配置只用既有upload，明确参数数组、仓库内工作目录、结果文件和可选查询数组，不拼接用户值形成shell，不新增普通步骤类型或执行器。
- **FR-017**: custom只接受已收集唯一原产物，核对原应用、版本、可信构建号、大小与摘要；配置JUnit必须封存通过，不能在审批后重建替换产物或证据。
- **FR-018**: custom执行前以原完整执行归属、产物/测试证据及明确应用绑定持久化发布意图并授执行权，同应用所有构建/项目受已有唯一绑定与保护。
- **FR-019**: custom仅在当前授权节点、有效执行权/剩余普通预算下执行，凭据只通过本次受限输入，取消与清理只影响本次资源，失权不能继续ordinary或always动作。
- **FR-020**: custom结果必须有界、严格、绑定原意图及产物；退出成功且有效回执才确认实际动作，不能把退出码当成已提交审核或公开发布。
- **FR-021**: 授权可能已提交后无可信结果、失联、取消或无效回执默认unknown，启动尚未回报同样保护；只有明确未发送/远端拒绝无副作用才failed并释放相应保护。
- **FR-022**: custom与内置发布沿同一持久授权/进度/日志/终态完整集合和独立停止确认边界，无自动重跑或更换意图重发；应用保护不由租约到期或物理停止自动解除。
- **FR-023**: 可选query命令只由管理员显式请求，经当前独立节点身份有限执行只读核对；无查询或证据不足保持unknown，不自动执行发布命令。
- **FR-024**: 人工确认须精确原意图/原摘要与充分非机密依据，同一决定幂等、冲突拒绝，不把查询空结果或停止确认当成无副作用证明。
- **FR-025**: custom输入、输出、日志和失败都不得公开秘密/参数或私有路径；原始工具输出不直接充当可信公开回执，含声明秘密的结果拒绝回传而不改写证据。
- **FR-026**: 原命令/取消/超时Reason优先，发布或清理失败不覆盖原失败；必要系统清理独立有限预算，清理未知仍停止后续执行并保留原证据。
- **FR-027**: 后续审批/自动触发沿同一冻结命名范围和权限接入，不在本功能伪造审批放行、changes自动基线或批量项目编排；通知未实现仍明确拒绝。
- **FR-028**: 管理方案、绑定项目或确认发布仅admin，构建触发沿既有角色；审批只读及节点身份不能借本功能修改方案或绕过授权。
- **FR-029**: 对方案来源、快照重试及custom授权/unknown竞争以两种现有持久后端执行相同实际行为门，并保留全量检查及一次整功能验收。
- **FR-030**: 四类方案及双平台组合须在前置能力正式验收后用真实工程验证版本、签名及中央原产物；自有custom接收端验证真实单次发送、丢回执、查询与取消，不用模拟执行替代。

### Key Entities

- **构建方案**：管理员命名的单构建完整定义、内置引用或本地内容摘要，不拥有执行身份或项目权限。
- **项目命名绑定**：项目中的稳定build名称、方案名称与已声明参数默认，来源集合整体选择。
- **来源快照**：原提交、实际来源与摘要及最终展开定义/参数/条件，入队后不随方案变化。
- **自定义发布意图与回执**：原应用、原产物、原执行归属、实际动作证据和unknown保护，沿既有发布记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四种方案分别能用于真实单平台工程，至少一组双平台命名构建可独立执行，所有实际版本/签名与中央产物一致；未完成前置验收不计成功。
- **SC-002**: 三来源与文件存在/缺失/损坏/无法读取的全部列明组合符合规则，错误输入零回退、零部分入队。
- **SC-003**: 全部声明参数覆盖、选择与权限正负例确定一致；20次相同触发只产生同一批结果，跳过记录不占构建号，秘密与私有路径零公开。
- **SC-004**: 方案、项目设置与分支更新后的实际原快照retry仍使用原定义/提交/条件/参数；旧任务与产物证据全部保持，四种内置摘要可追溯。
- **SC-005**: 自有接收端验证custom一次意图对应一次命令，合法回执可核对；故障/丢响应/启动前失联保持unknown，无第二次自动发送，停止确认不能解应用保护。
- **SC-006**: 错凭据/产物/报告/权限/失权/非法结果与查询不足全部安全拒绝或保unknown，同应用并发不绕锁，角色负例不占号或授发布权。
- **SC-007**: 两种持久后端执行同套来源/快照/custom用例，真实不同节点与独立子进程验证取消及无关进程存活，完整必要检查与收敛后一次本地提交。
- **SC-008**: 既有本地default/native/模板与远程repo项目、命名构建选择/预算/收尾/日志/下载行为回归通过，未实现功能未被误报支持。

## Assumptions

- 来源与范围依据docs/plans/BUILD_DISTRIBUTION.md、CONFIGURATION.md、INTERFACES.md、MVP_EXECUTION.md和SPECKIT_ROADMAP.md；既定目录名012-custom-workflows优先于本轮建议名。
- auto/profile不减少固定提交、可信仓库或项目当前权限检查；bindings是项目pipeline.builds的说明词，公开source枚举仍为规划的profile。
- 当前源码基线2602094含已验收008/019/020。005/009/010/011的真实具体代码接口冻结交付后串行集成；缺少Apple或商店材料不阻止独立组件实现、必要自动验证和代码交付，真实签名、上传与完整联合场景由用户最终统一人工验收，未执行不得记PASS。
- 014审批与015自动触发分别交付；本功能不替代它们，发布和查询语义沿两店已经规划的意图、应用保护及报告封存机制。
- 用户脚本属于管理员信任范围；系统限制自身启动/权限/输入及结果，不承诺识别任意脚本内部的远端发布或阻止其内部工具自行重试。
