# Feature Specification: Webhook自动触发、固定等待窗口与变更筛选

**Feature Branch**: `015-webhook-trigger-planning`

**Created**: 2026-10-05

**Status**: 已实施（必要自动验证见validation，四来源公网与完整人工矩阵待验）

**Input**: 用户要求沿既定015范围支持GitHub、GitLab、Gitee、自建Git的可信push触发；事件持久去重、固定quiet_period、重启原子关闭、真实changes筛选；复用当前构建链且不得扩大节点、应用、审批和发布权限。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员安全连接仓库推送 (Priority: P1)

管理员为已登记仓库启用一种来源，明确自动构建范围和密钥；开发者正常push即可请求构建，伪造、错仓库或未授权分支不能触发。

**Why this priority**: 自动化必须先证明来源可信和权限边界，不把公开入口变成任意构建或发布入口。

**Independent Test**: 四来源分别在自有仓库实际push，查询自动请求与构建记录；错误密钥、篡改签名、越界请求和身份交叉不会产生任务或编号。

**Acceptance Scenarios**:

1. **Given** 管理员已登记仓库及合法来源配置，**When** GitHub、GitLab、Gitee、自建Git各自实际push授权分支，**Then** 各收到一个持久自动请求，并沿同一构建链产生对应执行结果。
2. **Given** 一个项目已有合法密钥，**When** 请求密钥错误、签名体被修改、重复认证头、非法结构或超过限制，**Then** 请求安全拒绝，不产生事件、窗口、执行或编号，不回显密钥/原请求正文。
3. **Given** 项目限制仓库与分支，**When** 合法认证请求声称另一仓库、未授权分支，或使用请求URL替换仓库，**Then** 拒绝越权，不访问payload提供的URL；合法tag、PR、删除分支和provider可可靠识别的连接测试事件不执行构建。
4. **Given** 多个命名build或包含upload定义，**When** 管理员未明确选择自动范围或未允许自动发布，**Then** 不启用隐式全选/发布；即使upload的条件为false也不能绕过授权。
5. **Given** 现有用户与节点身份，**When** 非管理员更改自动策略或用户/节点token试作Webhook密钥，**Then** 拒绝；合法Webhook请求也不能扩大节点或应用权限、批准审批。

### User Story 2 - 重投与连续push形成固定窗口 (Priority: P1)

管理员设置等待时间以合并短时间连续push；每个接收事件可追溯，重复投递和重启不重复分号，持续push不能无限延后构建。

**Why this priority**: 事件重投常见，必须在外部请求与持久构建之间有明确且可恢复的边界。

**Independent Test**: 在30秒窗口内连续push、20个并发重复投递、乱序重投并重启控制端，检查窗口期限、最终SHA和项目编号。

**Acceptance Scenarios**:

1. **Given** 已接收一个事件，**When** 同一delivery标识并发重投20次，**Then** 只记录一次事件与一次归属，最多创建同一批结果；相同标识不同内容明确冲突。
2. **Given** 30秒窗口，**When** 窗口内连续push并在临近截止时追加，**Then** 首次截止时间不变，只更新候选信息；不同项目、来源、分支、静态build集合或参数输入不互相合并。
3. **Given** 新旧事件乱序或分支发生force push，**When** 窗口关闭，**Then** 核对授权仓库分支当时HEAD并固定真实提交，不因迟到旧payload选择旧SHA；解析、筛选和全部所选记录沿该SHA，不追逐之后的新HEAD。
4. **Given** 截止前或入队边界控制端退出，**When** 同一控制端恢复并存在并发关闭请求，**Then** 原窗口期限保留，最终结果与编号只提交一次；已排队/运行/待审批任务不被窗口改写或取消。

### User Story 3 - 只自动执行受变化影响的定义 (Priority: P2)

开发者为平台目录和公共代码配置changes；系统比较可信成功基线与固定提交，变化不影响某个build时记录跳过，首次或基线不可取得时保守完整执行。

**Why this priority**: 减少无关构建，同时不能因遗漏删除、改名、公共目录或缺失历史而静默漏构建。

**Independent Test**: 自有仓库依次新增、修改、删除、重命名、修改公共目录，再测试首构建、缺失基线、分支/参数/定义变化。

**Acceptance Scenarios**:

1. **Given** 同一比较范围存在成功基线，**When** 新增、修改、删除或重命名文件匹配changes，**Then** 执行对应build；重命名新旧路径均参与匹配，公共目录按声明正常影响多个build。
2. **Given** 无成功基线或原基线确实不可取得，**When** 收到合法push，**Then** 完整执行并记录固定原因；当前仓库读取、配置校验或diff解析失败仍报错，不能冒称缺基线/无变化。
3. **Given** changes、branches、params组合条件，**When** 变化与冻结参数/分支符合或不符合，**Then** 字段AND、列表OR规则一致；build跳过不占节点或编号，步骤条件仍在原顺序执行中生效。
4. **Given** 手动trigger、本地run或显式原快照retry，**When** 同一SHA的路径条件不匹配，**Then** 手动/local仍豁免changes但保留分支/参数条件；retry沿原条件事实，不重读当前HEAD/基线或变成自动触发。

### User Story 4 - 管理策略与故障证据可复核 (Priority: P2)

管理员可以启用、关闭和轮换来源密钥，查询去重、窗口、筛选与失败原因；构建权限与原始构建证据继续由既有系统管理。

**Why this priority**: 自动入口的配置变化、网络故障和未知执行必须可审计，而不是重投后静默产生另一批副作用。

**Independent Test**: 窗口内禁用、撤回发布授权、改变选择/参数，注入提交失败和来源不可达，再核对旧任务、密钥与查询角色。

**Acceptance Scenarios**:

1. **Given** 活动窗口，**When** 管理员关闭入口/轮换密钥或撤回授权，**Then** 旧密钥不再接收；关闭时重新检查当前策略，不能按旧授权发布，已存在执行的停止/unknown保护仍保留。
2. **Given** 两个不同参数或build选择的请求，**When** 同一SHA被自动请求、手动重跑或retry使用，**Then** 不按SHA永久全局去重；没有delivery ID的重复自动请求只合并同范围已有排队、运行、待审批或成功结果。
3. **Given** 全部所选配置必须合法，**When** 某个build参数错误、来源失败或入队事务失败，**Then** 不部分创建结果或消耗编号；查询显示固定失败原因和原事件关系，不泄露配置正文、密钥或私有仓库路径。
4. **Given** 两种持久存储与macOS/Linux控制端、节点，**When** 运行相同事件、窗口、权限、changes和恢复门，**Then** 结果一致；执行继续复用既有租约、审批、报告、日志和产物规则，不自动迁移或重发未知发布。

### Edge Cases

- 无delivery ID、同ID异正文、provider别名头混用、请求携带不同认证模式、正文包含密码字段、分支名控制字符或伪SHA。
- quiet_period=0、截止时间恰好到达、已到期但未关闭窗口又收到新事件、乱序/强推/分支删除、关闭准备期间再收到事件或策略变化。
- 多build定义变化、单build唯一名称改名、参数未声明/默认值变化、空build列表与重复名称、upload条件false、approval跳过、无合格节点。
- 同SHA但不同参数/范围、成功基线来自另一分支/参数/定义、基线丢失/非祖先、超过变化限制、非法Git路径、改名被Git判成新增与删除。
- 接收提交前/后、关闭提交前/后退出；锁丢失、响应丢失；不能把已确认事件等同于已执行或已公开发布。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 支持GitHub、GitLab、Gitee及管理员登记的自建Git来源；每项目以登记provider解释请求，不凭外部头切换来源。
- **FR-002**: 只有管理员可启用、关闭、轮换密钥或导入自动策略；仓库流水线/构建方案不能自行启用入口、改变选择范围或允许发布。
- **FR-003**: 密钥受限保存、与用户/节点/Git认证材料隔离；只在明确初始化/轮换时向管理员提供一次所需秘密，列表/日志/快照不含明文，token不放URL。
- **FR-004**: 请求读取、认证头、事件结构、SHA/分支及变化数据都有明确有限边界；超限或歧义安全失败，无外部动作。
- **FR-005**: 在解释事件或创建持久请求前验证原始请求与provider实际认证方式；签名检查不能改写正文或使用宽松回退，不能给无真实时间戳的来源发明时间戳要求。
- **FR-006**: 一期只由正常分支push触发；provider可可靠识别的连接测试、tag、PR和删除分支事件明确忽略，不生成构建。
- **FR-007**: 事件分支必须为完整普通分支引用且符合项目授权，提交必须是合法完整SHA；HEAD与可达性由已登记仓库核实。
- **FR-008**: 核对事件所属仓库与登记身份；payload仓库/compare等URL不能替换可信仓库或成为网络读取来源。
- **FR-009**: 自动选择来自管理员的triggers.builds；多build必须显式选择，单build才可推导唯一名称；静态选择集合与参数输入明确冻结，不隐式全部。
- **FR-010**: 只要任何所选定义含upload就需要管理员明确allow_upload，即使when=false；节点、应用归属、报告和approval授权必须继续独立验证。
- **FR-011**: 接收成功响应前持久提交事件去重信息及窗口归属；失败不留下已成功接收的假记录。
- **FR-012**: 有delivery ID按项目/provider/标识去重；精确重投返回原归属，同标识异内容冲突，不能再开窗口或分号。
- **FR-013**: 无delivery ID自动请求按项目、build、分支、SHA、参数及冻结选择/定义范围合并已有排队、运行、待审批或成功的自动结果；不同输入、手动重跑与retry不受此永久去重。
- **FR-014**: 窗口按项目、来源、分支、静态build集合、参数输入与策略版本隔离；只有相同范围且在原接收区间内的事件可合并。
- **FR-015**: quiet_period为非负等待时间，默认0；首事件固定起点和截止时间，后续事件不延长，截止后的新事件形成下一窗口。
- **FR-016**: 关闭核实授权分支HEAD并冻结一个真实最终SHA，事件乱序不能选回旧SHA；后续HEAD推进不能改变本次快照。
- **FR-017**: 在固定SHA解析唯一流水线来源、选择、最终参数、when和changes；所有所选配置/权限校验后才原子生成结果与编号。
- **FR-018**: 持久窗口跨控制端重启保留原期限，关闭/结果/编号一次提交；并发或重复关闭不重复入队，不改既有任务。
- **FR-019**: 真正入队前复核当前项目/分支/build选择/发布授权及比较基线一致；禁用或策略变化不得沿旧权创建任务。
- **FR-020**: 每个build比较同项目、同分支、同最终参数、同静态选择/定义范围的上次成功SHA，基线身份、SHA和改动事实保存，不使用另一范围的成功记录。
- **FR-021**: 首构建或比较基线确实缺失/不可取得时按完整构建并记录原因；目标仓库/配置、权限、资源超限或diff错误不冒称缺基线。
- **FR-022**: changes用区分大小写的仓库相对路径glob；新增/修改/删除有效，改名新旧路径都参与；公共目录由用户显式声明，不偷偷推断平台。
- **FR-023**: build与step的when沿同一条件规则：字段AND、列表OR、参数逐项AND；有效变化事实供整个原执行使用，不从工作区或后续HEAD重新计算。
- **FR-024**: build条件不满足保存skipped/原因，不占节点、编号或成功通知；全部普通步骤跳过不执行post，原失败/取消和步骤顺序不被changes改写。
- **FR-025**: 手动trigger/local默认忽略changes但保持其它when；retry固定原SHA/定义/参数/条件事实，新身份和编号沿既有重试规则，不经过窗口。
- **FR-026**: 管理员/获准读证据身份能查询事件、合并窗口、最终结果、固定基线/变化摘要与失败原因；安全记录不含原payload、密钥、个人提交信息或私有绝对路径。
- **FR-027**: 自动触发沿同一执行链、节点权限、租约、审批/应用锁、报告封存与unknown保护；不能自动迁移已开始任务、确认未知发布或运行第二套执行器。
- **FR-028**: 四来源、两种持久存储及macOS/Linux的实际接收、去重、窗口恢复、changes和执行链必须有真实证据；没有来源/授权材料时保留未验收门，不能以自制payload代替真实provider push。

### Key Entities *(include if feature involves data)*

- **来源配置**：项目provider、仓库身份、启用状态、独立密钥身份、自动build选择、等待时间和发布策略；由管理员维护。
- **接收事件**：安全身份、正文摘要、分支/提交、接收时刻与去重标识；关联唯一归属窗口或忽略原因，不保存秘密正文。
- **固定窗口**：隔离范围、首接收与固定截止、合并事件、关闭结果及最终SHA；退出后可核对恢复。
- **变更事实**：build比较范围、可信成功基线、最终提交、规范变化路径与完整构建原因；随快照固定。
- **自动批次**：关联窗口与独立build执行/跳过结果；沿项目共享计数器和既有执行证据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四来源各至少一次实际授权push产生对应持久结果；各至少一次错误凭据/认证被拒，不产生编号或执行。
- **SC-002**: 同delivery20个并发重投只产生一次归属与一批结果；同标识异输入100%冲突，不出现重复编号。
- **SC-003**: 30秒窗口中最后一秒继续push仍保持原截止；自有正常可读仓库中截止后60秒内形成唯一结果，分支/参数/选择范围隔离全部正确。
- **SC-004**: 接收与关闭的提交前后四个退出点恢复后，不丢已确认事件，不重复已确认结果或编号，不改写正在执行的原快照。
- **SC-005**: 新增/修改/删除/改名双路径/公共目录、无变化、首次/缺基线、分支/参数/定义隔离的用例结论100%符合冻结规则；手动豁免与原快照retry均正确。
- **SC-006**: 所有公开列表/错误/日志/快照均不含测试秘密、原payload或私有绝对路径；禁止自动发布、approval跳过与节点/应用越权门均拒绝且无对应副作用。
- **SC-007**: 两种持久存储运行同一事务、去重、计数器、权限与重启用例，macOS/Linux真实构建节点执行相同固定快照与变化结论；源码检查和真实来源门均保留。

## Assumptions

- 唯一产品范围是GitHub/GitLab/Gitee/generic自建Git；Gitea/Gogs只作为自建兼容研究，不替代Gitee或新增必验provider分支。轮询、cron和通知仍后续，不实现通用Webhook脚本框架。
- 006/007已验收，当前只从85b46bf准备spec/plan；008、012、014、019均未作为已验收基线。实现必须等008/012/014正式验收集成，涉及报告/发布/审批继续保留其各自真实门。当前不存在的014具体类型不假称已冻结。
- 项目Repository登记后不可变；自动配置来自管理员，不读取宿主未知凭据。外部入口由验证TLS的部署代理公开，provider使用其官方JSON push格式；旧form编码不纳入MVP。
- 没有delivery ID不能保证外部事件恰好一次，只承诺所述同范围自动结果的持久合并；有ID也不承诺商店副作用恰好一次。
- 窗口隔离加入策略版本、changes比较隔离加入参数/静态选择/定义摘要，是防止授权或配置改变后复用旧条件的最小安全选择，不新增构建DSL。成功基线可来自同范围手动/retry的成功构建，但这些构建自身不受自动事件去重。
- 有限请求与等待/比较预算的具体数字在plan/contracts冻结；quiet_period默认0来自产品，任何更长上限属于本次实现选定边界，不冒称既有硬要求。

## 最终实施与人工验收安排

用户最新授权各模块完整实现、必要自动检查与案例先交付；四个外部来源真实push、合法Apple材料和真实商店发布由用户人工验收。当前代码消费已交付008/012/014/019/020及010/011真实接口，保留全部来源/执行/未知边界，不因待人工门留下占位实现。未实际运行的大矩阵及外部门明确待验，不据自有generic案例宣布四provider完成。
