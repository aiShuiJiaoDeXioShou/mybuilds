# Feature Specification：Google Play 发布与未知结果核对

**Feature Branch**：`010-google-play-planning`
**Created**：2026-10-05
**Status**：规范草案；正式实现与验收须等待008、009、019交付。
**Input**：用户确认完成全部MVP；依照产品规划，实现Google Play真实internal分发、明确的production授权、原产物与测试证据绑定，以及失联后不会自动重复上传的核对流程。

## User Scenarios & Testing

### User Story 1 - 发布本次已验证的 Android 产物（Priority: P1）

管理员为项目绑定已准备的Google Play应用，选择具备授权材料的节点。构建生成唯一AAB，完成声明测试后发布到internal，查看原构建、产物与商店版本的关联。

**Why this priority**：这是Android构建进入主要分发渠道的最小完整路径。
**Independent Test**：实际构建已准备应用，以默认轨道上传，核对真实可见应用、构建号和版本。

**Acceptance Scenarios**：

1. **Given** 已授权应用与节点、唯一签名AAB且声明测试已通过，**When** 管理员发起含上传的构建而未指定轨道，**Then** 只向internal执行一次上传，保留原产物摘要、测试证据、发布意图和可查询回执。
2. **Given** 原生或Flutter生成的有效AAB，**When** 选择一个命名build发布，**Then** 使用该build的原固定产物和构建号，不以另一build产物替代。
3. **Given** APK、多匹配AAB、损坏包、错误应用或包内版本不符，**When** 请求发布，**Then** 外部上传前明确拒绝；声明测试缺失、失败或证据改变也不能上传。
4. **Given** 缺工具、授权材料、应用权限或首次接入前提，**When** 诊断或发布，**Then** 明确指出缺失项，不交互登录、不自动接受协议。

### User Story 2 - 明确授权并串行发布同一应用（Priority: P1）

管理员控制应用项目归属、轨道与公开发布。同一应用不因项目、build或节点不同而并发上传，不静默替换已有版本。

**Why this priority**：防止错误应用、意外公开发布与构建互相覆盖。
**Independent Test**：同一应用20次并发申请，至多一次获得发布权；验证权限、production选择和版本冲突。

**Acceptance Scenarios**：

1. **Given** 非管理员或没有明确上传许可，**When** 发起含上传定义的构建或retry，**Then** 拒绝，不授予上传执行权；跳过审批不隐式放行上传。
2. **Given** 未明确选择production，**When** 普通发布、重试或恢复，**Then** 保持原明确轨道或默认internal；仅管理员明确选择production才可能公开发布。
3. **Given** 应用已核验绑定项目A，**When** 项目B绑定或发布同一商店应用，**Then** 拒绝；A的各build和节点仍共用同一应用保护。
4. **Given** 同应用无活动发布，**When** 20个不同申请竞争，**Then** 最多一个获得执行权，其余明确等待或拒绝，未持久化意图不能运行命令。
5. **Given** 商店已有相同或不兼容构建号，**When** 请求发布，**Then** 明确失败，不覆盖、不暗改计数器、不重新构建。

### User Story 3 - 中断后核对原发布而不重复发送（Priority: P1）

管理员查看未知结果、查询远端并审计人工确认。构建取消、节点停止与重启不是再次上传的理由。

**Why this priority**：远端副作用不能靠本地进程状态证明。
**Independent Test**：真实发布完成后丢失回执，unknown持续保护；重启与重复请求不再次上传，精确核对后才更新原结果。

**Acceptance Scenarios**：

1. **Given** 已持久化并授予发布执行权，**When** 节点在命令启动前后失联或回执缺失，**Then** 默认unknown并保留应用保护；未报告启动不等于未发送。
2. **Given** unknown原发布，**When** 控制端/节点重启、构建retry、重复回报或确认进程已停止，**Then** 不重发原上传，停止确认不解除应用保护。
3. **Given** 原应用、版本、构建号与产物证据，**When** 管理员显式查询并取得足以关联原发布的结果，**Then** 更新原记录并保存查询审计；无匹配或查询失败仍unknown且不上传。
4. **Given** 查询不足以确定结果，**When** 管理员提供原意图、确认结果与依据，**Then** 只更新精确原意图；非管理员、错归属、冲突或仅退出状态拒绝，相同决定幂等。
5. **Given** 可信证据确证未发送或远端明确拒绝，**When** 确认失败，**Then** 记failed并解除该条保护；连接错误、超时或进程非零本身不是该证据。

### User Story 4 - 查询真实状态并保护凭据（Priority: P2）

用户查看脱敏状态与关联证据，区分工具动作完成、版本上传与公开发布，不一直占用节点等待商店处理。

**Why this priority**：分发结果可核验，不能把退出码当成已上架。
**Independent Test**：比较真实商店查询与客户端结果；核对权限并扫描输出中的测试机密。

**Acceptance Scenarios**：

1. **Given** 工具成功但没有公开可见证据，**When** 查看详情，**Then** 最多记录已证实的uploaded/processing等状态，不声称published，后续查询沿原远端身份更新。
2. **Given** 上传动作完成但商店仍处理，**When** 查询状态，**Then** 构建槽已经释放，查询不上传、不占构建槽。
3. **Given** 凭据包含测试机密且工具失败，**When** 查看表格/JSON、日志与错误，**Then** 不出现机密、完整脚本、凭据私有路径或完整环境；拒绝身份不可读取发布详情。

### Edge Cases

- 多项目、多build、多节点竞争同一应用；改组不能改变应用归属。
- 包被链接替换、收集后改变、正确摘要但错误应用/版本、审批后报告被改。
- 构建取消或租约过期，但远端仍处理；旧完整执行身份不能取得新发布权。
- 意图持久化失败、授权响应丢失、第三方工具内部非幂等重试、远端接受后连接断开。
- 外部发布推进构建号；查询无匹配、多候选或权限不足。
- 未声明测试不伪造通过；已声明必须封存通过证据。
- unknown与查询/确认竞争、重复决定、证据清理；未知记录及关联原产物持续保护。
- 本地有效upload在任何用户动作前拒绝；dry-run不访问商店。

## Requirements

### Functional Requirements

- **FR-001**：支持管理员发布唯一AAB，默认internal，允许明确指定的合法测试轨道。
- **FR-002**：原生与Flutter Android产物共用同一平台分发、授权和安全规则。
- **FR-003**：诊断节点实际工具与版本、应用授权及接入条件；缺失明确失败，不自动登录、接受协议或更新工具。
- **FR-004**：凭据只来自授权节点受限材料引用，不出现在明文命令参数、快照、中央记录、日志、公开输出和错误；不继承完整控制端/节点环境。
- **FR-005**：上传前核对唯一已收集AAB的普通文件边界、摘要、结构、签名、应用、版本与构建号；错误或改变必须拒绝。
- **FR-006**：发布绑定原build名称、提交、配置、参数、构建号、节点、完整执行身份、产物与声明测试封存证据，禁止重新构建或替换。
- **FR-007**：声明测试须全部通过并封存；缺失、失败、错误或之后改变拒绝；未声明不得伪造通过证据。
- **FR-008**：含上传定义的触发与retry保持管理员与明确上传许可校验；条件跳过审批不视为批准。
- **FR-009**：production须管理员在配置或请求中明确选择，默认、重试、查询和恢复不得扩大公开发布。
- **FR-010**：已核验商店应用唯一绑定项目，拒绝跨项目绑定；同项目各build/节点共用应用保护，组迁移不改变绑定。
- **FR-011**：持久化意图与应用保护后才授予发布权；20并发至多一次授权，持久化失败不得启动外部命令。
- **FR-012**：商店版本冲突明确拒绝，不覆盖、不暗改构建号、不改原产物。
- **FR-013**：发布在普通构建与测试之后，受原累计预算、租约、取消和节点授权约束；旧完整身份不能取得新动作权。
- **FR-014**：一次授权绑定一次命令调用；不自动重跑整条上传，须核验所用第三方工具在不可确认副作用后不会自动非幂等重发。
- **FR-015**：已授权但缺可信终态回执默认unknown，包括启动前后失联；保护跨重启保持，不迁移/重放原动作。
- **FR-016**：unknown阻止同应用后续上传；构建retry、取消、节点停止确认和工具退出码不能自行解除保护。
- **FR-017**：仅可信证据确证未发送或远端明确拒绝才可failed并解除保护；一般网络错误、超时和非零退出不足。
- **FR-018**：管理员可按原意图显式查询应用、版本与构建号；查询不上传、不占构建槽，无充分结果仍unknown。
- **FR-019**：管理员可有依据地人工确认精确原意图，保留身份、时间、依据和结果；拒绝错归属/冲突，相同重复决定幂等，仅停止证据不足。
- **FR-020**：区分uploaded、processing、submitted、published、failed、unknown并记录远端标识，只记录已证实适用状态；退出0不证明published。
- **FR-021**：上传动作结束后释放构建槽，不等待外部处理；后续查询不重建/重传。
- **FR-022**：客户端提供发布列表、详情、显式查询与确认；表格/JSON一致脱敏，沿已有角色拒绝越权，不显示机密、私有路径或完整脚本。
- **FR-023**：unknown、应用保护与关联原产物、报告、构建关系受保留保护；后续清理不得删除这些证据，须联验。
- **FR-024**：本地有效upload在任何脚本前拒绝；dry-run不读取节点密钥、不访问商店。
- **FR-025**：与008恢复、009框架/节点及019报告按现有规范集成，保留已有本地构建、远程节点归属和原证据行为，不因增加发布渠道改变原构建语义。
- **FR-026**：验收包括真实internal可见、错凭据/应用/版本、20并发、丢回执unknown、重启无重发、查询/确认、证据变更及必要检查；缺条件记录待真实验证，不以模拟商店结果宣称完成。

### Key Entities

- **应用绑定**：商店应用的唯一项目归属、核验与轨道授权。
- **发布意图**：原构建/完整执行归属、应用、轨道、版本、构建号、产物摘要、封存报告与一次动作身份。
- **应用保护**：同一应用的一次活动或未知发布占用，独立于构建槽。
- **发布回执**：已证实状态、远端标识、原意图与原证据，不等于退出码。
- **核对决定**：查询或人工确认的原意图、身份、时间、依据、结果及重复/冲突审计。

## Success Criteria

### Measurable Outcomes

- **SC-001**：实际原生和Flutter AAB各一次沿同一分发路径进入已准备应用internal，远端应用/构建号/版本正确，默认不会公开发布。
- **SC-002**：错误包/应用/版本/摘要、多产物、声明测试失败/缺失/改变、无权限、过期权与未授权production全部在上传前拒绝。
- **SC-003**：20并发同应用申请至多一次授权；重复请求、冲突回报与重启不产生同一意图的第二次上传。
- **SC-004**：真实上传丢回执后持续unknown保护；重启/停止确认保持，仅查询或有依据的精确确认才更新。
- **SC-005**：所有公开输出不出现注入测试机密，不同读取/修改权限身份均与授权一致。
- **SC-006**：上传结束节点可继续排队任务，无须等待商店处理；查询不再上传、不声称未经证实的published。
- **SC-007**：全部场景保存真实证据，必要检查与收敛无阻塞；缺应用/凭据等条件明确待真实验证，不能标完成。

## Assumptions

- 依据docs/plans/BUILD_DISTRIBUTION.md、MVP_EXECUTION.md；本次只提前准备规范，实施仍须008、009、019原依赖。
- 用户准备商店应用、必要首次上传/协议、service account授权与签名；不创建账号、接受协议、补商店素材或隐私声明。
- 实际验收默认internal；公开上线不作为默认测试动作，审核等待不作为完成时限。
- 仓库可信；普通shell自行发布不能获得内置发布核对保证，upload是受控入口。
- 工具锁版本/内部重试、消息和查询/确认格式在后续plan确定，此规范不编造实现或验证。
- 014审批、020保留后续以真实状态联验；当前尚不支持的生效审批不能绕过。
