# 功能规范：Flutter 双平台构建与可编辑模板

**Feature Branch**: `009-flutter-builds`

**Created**: 2026-10-04

**Status**: 需求范围冻结；组件实际实施中；代码与必要自动检查先交付，真实签名／双平台联验由用户最后统一人工验收

**Input**: 按既有 MVP 产品规划提供 Flutter Android/iOS 体检、单文件单／双平台初始化、版本与 flavor 参数、真实签名产物及取消验收；复用已有原生能力和多节点执行边界。本轮按用户最新要求推进完整代码与必要自动检查；005真实接口按组件冻结交接，不创造替代类型或stub。实际签名、双平台构建与远程最终联验独立记录，交付源码不代表这些人工门已通过。

## 用户场景与测试

### 用户故事 1 - 检查环境并初始化 Flutter 流水线（优先级：P1）

开发者在已有 Flutter 工程检查所选目标平台的工具与明确声明的签名前提，生成可直接编辑的流水线，而无需手工拼接两份配置。

**优先原因**：先定位缺失前提，再让单平台与双平台共用同一配置、选择和参数规则。

**独立测试**：在自有临时目录执行初始化与纯预览；在实际安装及缺失／错误工具环境检查体检的安全结果，不运行应用构建或使用未知签名资源。

**验收场景**：

1. 给定空目标目录，执行 `mybuilds init --framework flutter --platform android` 或 `ios`，生成一份合法配置，仅包含所选名称的 build；选择 `android,ios` 时同一 YAML 恰好包含这两个 build，不重复根字段或改为两个文件。
2. 给定已有目标文件、重复／未知平台或与本地自定义模板冲突的选项，初始化失败且目标字节不变；无参数 init、原生模板与自定义模板名称保持原有行为。
3. 给定已声明所需参数但没有密钥值的双平台配置，纯预览能显示平台、顺序、参数与待确定上下文；不执行 Flutter、签名准备、网络或脚本，也不创建工作区／结果目录。
4. 给定可实际调用的 Flutter 与目标工具链，体检报告实际版本和逐项状态；缺失、无法执行、不兼容、超时或被取消时返回固定诊断。Android 体检不因无 Xcode 失败，iOS 不因无 Android 工具失败；未声明签名材料单独显示未检查，不能冒称签名已通过。
5. 给定工具正常但显式签名材料错误，体检标明失败且不泄露密码、材料正文或未知宿主身份；体检不自动升级 Flutter／平台 SDK、接受许可证、创建签名材料或更改用户工具配置。

### 用户故事 2 - 构建版本和 flavor 正确的 Android 产物（优先级：P1）

开发者从真实 Flutter Android 工程得到可核验的发布包及测试安装包，明确控制版本、构建号和应用变体，并能增加自己的构建／测试脚本。

**优先原因**：交付可供下载和后续分发复用的真实构建证据。

**独立测试**：用本次自有工程和测试 keystore 构建，独立读取 APK/AAB 元数据与签名；修改参数和 flavor 后实际产物与请求一致。

**验收场景**：

1. 给定已配置 release 签名的真实工程，模板生成 AAB 和 APK，实际应用标识、市场版本、构建号及签名均与本次声明一致；结果清单可逐字节复算大小和摘要。
2. 给定已准备的 Android flavor，非空参数确实选择该变体，其应用标识／可辨识内容与默认变体不同；空 flavor 不传显式 flavor，沿工程自身默认行为。不识别的 flavor 或非法版本安全失败，不静默构建另一个变体。
3. 给定开启 R8 且声明 mapping 的工程，收集本次对应 mapping；未开启混淆的工程可编辑收集声明，不把 mapping 缺失伪装为存在。旧 APK/AAB/mapping 不得混入本次快照。
4. 给定开发者添加仓库脚本并通过显式环境映射传入 version、channel、flavor 等参数，普通步骤实际消费参数；含空格或 shell 特殊字符的合法值不成为额外命令，未声明／不合法参数在任何所选用户脚本前拒绝。
5. 给定错误 JDK、SDK、签名密码／alias 或工程硬编码版本，实际构建或核验失败并保留安全原因；已准备缓存可复用，运行不自动更新平台 SDK 或改写源工程的版本／签名配置。

### 用户故事 3 - 使用明确材料构建签名有效的 iOS 产物（优先级：P1）

开发者在 macOS 的真实 Flutter iOS 工程中使用明确授权的证书与描述文件生成 IPA、归档和调试符号，无需依赖系统中未知的签名身份。

**优先原因**：iOS 发布包必须有真实、可核验的签名及版本证据，资源安全不能由用户自行编写清理脚本承担。

**独立测试**：在真实 Apple 材料和兼容工程上完成 archive/export，独立核验 IPA、对应归档／符号和原有用户资源；没有材料时明确记录待验证。

**验收场景**：

1. 给定已授权且匹配的工程、应用标识、P12、profile 和密码环境引用，构建得到签名有效的 IPA、对应可下载归档包与压缩 dSYM；实际应用标识、版本和构建号符合本次声明，清单摘要可复算。
2. 给定已共享且正确配置的 iOS flavor scheme，构建选择该变体并核验对应应用身份；空 flavor 不强制猜测 scheme，缺失或不匹配的配置明确失败。模板不擅自修改工程来创建 flavor。
3. 给定过期／错团队／错应用／错证书的材料，整批执行前拒绝且不启动前一个 build 的用户脚本；真实构建版本不符或缺少对应符号时，不能给出完整成功产物结论。
4. 给定实际成功、准备半失败、归档／导出失败、取消或用户 post 失败，只清理本次临时 keychain、profile 副本和隔离临时目录，用户 default/search list、未知身份及无关进程不变。资源清理具有独立有限预算，原失败原因和清理失败分别保留。

### 用户故事 4 - 本地与远程执行保持同一取消和证据边界（优先级：P1）

开发者用同一配置本地调试或在已授权节点构建，分别查看两个 build 的真实进度、日志和产物；Flutter 不能绕开已有执行、签名和停止保护。

**优先原因**：框架变化不应扩大节点授权、泄露密钥或使中断任务被重复执行。

**独立测试**：在实际 macOS／Linux 节点执行 Flutter Android，并在具备真实签名能力的 macOS 节点执行 Flutter iOS；观察取消、失权、完整产物下载和资源清理，不以模拟工具替代构建。

**验收场景**：

1. 给定双平台配置与合法选择，既有单 build、显式多 build 和全选行为保持；本地整批预检查后按选择顺序执行，实际一项失败不会自动取消另一个可继续的 build，清理或进程停止未确认时停止后续启动。条件全跳过或仅选择收集步骤不准备 iOS 签名资源。
2. 给定实际普通步骤、签名准备、归档／导出或 post 正在运行，用户取消／累计超时回收本次前后台子进程；独立收尾预算不重置普通预算，系统签名清理不依赖用户 post。无关进程保持存活。
3. 给定没有 Flutter 或缺少目标工具／签名能力的节点，任务保持排队且说明原因，管理员标签单独不足以证明能力；iOS 不分配给 Linux。具备能力且在项目授权范围内的节点执行冻结提交，中央下载的完整产物与节点快照大小／摘要相同。
4. 给定远程用户取消，停止普通构建，仍按既有规则在有效执行权和独立预算内处理被选中的用户 post；租约过期、撤销执行权或进度保存失败时，不启动任何新的构建或用户 post。系统安全清理仍执行，无法确认停止时保留节点隔离及同名互斥，旧执行不能补报成功。参数不能伪造服务端构建号或签名资源事实。
5. 给定已完成完整收集后发生取消或日志收尾失败，保留对应完整诊断快照和原失败原因；不把诊断快照当成成功发布。日志、预览、任务快照与公开结果均不含本次敏感标记。

### 边界情况

- Flutter/Dart 版本无法解析、路径有空格、工具存在但实际无法执行、工具初始化超时、仅一个目标平台可用。
- 双平台未显式选择、重复／未知平台、已有配置、内置选择与自定义模板冲突、所有 build 条件跳过、仅执行 artifact。
- 非空 flavor 与工程变体不匹配、工程自带默认 flavor、flavor 改变应用标识、参数含特殊字符、版本格式或平台构建号越界。
- 依赖下载失败、复用缓存、用户要求离线但缓存未准备；不能以升级 SDK 或回退到其他版本掩盖失败。
- release 实际使用 debug 签名、空／错误密码引用、P12/profile 错配、iOS 原生签名支持不可用或材料不足。
- 前一 build 可执行但后一签名配置非法、取消发生于资源准备／编译／导出／post、系统清理失败、旧文件及被替换自有路径。
- AAB/APK/IPA 的版本或身份不符、应有 mapping/dSYM 缺失、收集后取消、回传中断或摘要不符。
- 管理员标签声明 Flutter 但工具失败、Linux ARM 上 Android 二进制不可执行、失权后迟到回执、密钥变量名与受限系统环境冲突。

## 需求

### 功能需求

- **FR-001**：提供 Flutter Android、iOS 单平台及 `android,ios` 双平台本地初始化；同一 YAML 生成相应 android／ios 命名 build，非法／重复平台拒绝。
- **FR-002**：内置 Flutter 模板可完整编辑，默认仅构建／收集，不添加审批、上传或通知；沿用已有 run/artifact，不增加 Flutter 专属步骤或另一套执行流程。
- **FR-003**：初始化拒绝覆盖已有文件，内置选项不与自定义模板混用；无参数、原生及已有自定义模板行为保持。
- **FR-004**：复用已有选择、参数校验、when 和纯预览；双 build 须显式选择，预览不启动任何外部动作、不读取密钥、不准备资源。
- **FR-005**：本地 Flutter 体检检查实际 Flutter/Dart 版本及所选平台工具；缺失、无法执行、不兼容、超时、取消均给出安全逐项状态，不以文件存在代替执行。
- **FR-006**：体检只要求所选平台前提，显式材料才检查签名；未声明材料显示未检查，不能自动选用宿主身份或报告签名能力通过。
- **FR-007**：体检／构建不自动升级 Flutter、Android SDK 或 Xcode，不接受新许可证，不管理开发者账号、设备或签名材料；现有已授权缓存可复用，依赖缺失明确失败。
- **FR-008**：模板声明 version、channel、flavor 和本地 build_number 字符串参数；version 默认 1.0.0，build_number 默认 1，channel 默认 internal，flavor 默认空。市场版本采用三段非负十进制整数，本地构建号为正十进制整数并满足所选平台上限；version 与构建号须由实际构建消费，并独立核验产物，不能仅显示传入值。
- **FR-009**：flavor 默认空，仅非空时显式选择 Flutter flavor；用户工程负责准备 Android 变体与 iOS 共享 scheme，不能静默回退或自动创建变体。channel 表示用户渠道参数，不改变 Flutter SDK 分支或替用户发布。
- **FR-010**：参数通过显式受限环境映射供可编辑命令／仓库脚本消费，不把参数拼成额外命令，不自动导出全部参数；用户不能覆盖受保护的构建上下文或签名事实。
- **FR-011**：Android 默认模板实际构建签名 AAB 和 APK，核验应用标识、versionName/versionCode 与本次声明／预期签名；不能以 debug 签名冒称指定 release 签名成功。
- **FR-012**：复用已有 Android 工具与明确签名引用规则，并给出真实 Flutter 工程接入示例；不假设原生 Gradle 参数已被任意工程消费，不写入明文密码或改写用户签名配置。
- **FR-013**：mapping 仅在工程确实开启混淆且声明收集时要求并核验；文档明确无 mapping 工程需相应编辑声明，不虚构产物，不把旧变体／旧构建文件算作本次输出。
- **FR-014**：iOS 默认模板使用显式 ios_signing 材料环境引用，复用已有签名校验与临时资源生命周期，生成签名有效 IPA、对应可下载归档包和压缩 dSYM，独立核验应用标识与市场／构建版本。
- **FR-015**：iOS 模板和示例明确工程／scheme／应用身份／导出方式的必要前提；使用明确材料且与 flavor 身份匹配，不使用未知宿主私钥，不自动注册或下载签名材料。
- **FR-016**：iOS 签名资源按构建隔离，未开始／条件跳过／仅收集不准备；普通步骤、artifact、用户 post 之后执行独立有限预算系统清理，部分准备失败同样清理，密码不进入进程命令行。
- **FR-017**：临时 keychain、profile 副本与外部临时目录只按本次真实所有权清理；不改用户 default/search list，不删除被替换／未知资源，清理不确定阻止后续启动并单独保留原因。
- **FR-018**：所选整批配置、参数、工具与显式签名前提在任何用户动作前检查；生效而尚未实现的审批／上传等功能明确拒绝，不静默跳过或假成功。
- **FR-019**：所有构建和用户脚本复用已有受限环境、累计普通预算、独立 post、进程组取消及 UTC 脱敏日志；取消仅回收本次进程，原失败／取消与收尾／清理失败分别保留。
- **FR-020**：产物来自本次明确输出与独立快照，沿用路径／符号链接限制、完整清单、大小与 SHA-256；保留真实完整诊断副本，部分或旧输出不得变成成功证据。
- **FR-021**：远程构建复用既有节点身份、项目授权、精确标签与实际工具能力匹配；Flutter Android 仅在实际可执行所需工具的 Linux/macOS 节点运行，Flutter iOS 只在有已验收签名支持及明确材料的 macOS 节点运行。
- **FR-022**：Flutter 能力检查进入既有节点诊断与调度，声明标签或 OS/CPU 名称不能冒称能力；没有合格节点保持排队，原生／通用任务匹配不退化，不新增节点协议或调度体系。
- **FR-023**：远程版本／参数／条件来自冻结任务；构建号使用控制端分配的可信编号，用户本地构建号参数不能替换远程编号。每个 build 有独立执行、日志与产物，双平台不强制相同构建号、不增加 build 间依赖。
- **FR-024**：远程执行遵守现有动作前授权、剩余预算、停止确认及完整证据边界；用户取消依既有规则处理普通步骤和被选中的有限预算 post。失权或保存失败禁止新的用户动作／post、旧终态补传和自动迁移／重跑；系统安全清理独立执行，不代表获得用户收尾权限。
- **FR-025**：同一真实 Flutter 工程覆盖默认与非空 flavor、可编辑仓库脚本、Android/iOS 本地及远程构建；Android 在实际 Linux 和 macOS 工具环境验证，iOS 在授权 macOS 签名环境验证，交叉编译不代替工具执行。
- **FR-026**：版本／签名／产物、错误工具／材料、取消／超时／post 失败、敏感输出和无关资源不变均有真实可重复验收；模拟 Flutter 命令、unsigned IPA、自产非 Apple profile 或预置文件不作为成功产物证据。
- **FR-027**：记录实际工具版本、授权资源引用、提交、命令、脱敏结果与证据位置；缺少真实 Apple 材料时保留待验证状态，不降低 005 或全 MVP 的真实签名门。
- **FR-028**：保持框架、目标平台与发布渠道分离；本功能不实现商店上传、无仓库 YAML 的方案绑定、自动依赖／SDK 安装、插件框架或应用工程迁移。

### 关键实体

- **Flutter 构建模板**：可编辑的单文件定义，含平台命名 build、参数、目标前提、普通构建和收集声明；双平台组合保留两个独立定义。
- **Flutter／平台体检证据**：实际工具版本、所选目标、已检查与未检查的签名前提、安全失败原因；标签不能替代证据。
- **本次构建身份**：冻结工程提交、名称、版本、实际构建号、flavor、预期应用／签名与对应输出。
- **本次签名资源**：明确授权材料引用、隔离临时资源及独立清理证据；不包含公开密码。
- **本次产物证据**：APK/AAB 或 IPA/归档／符号、条件性 mapping、真实版本／签名与不可混入旧文件的快照清单及摘要。

## 成功标准

### 可衡量结果

- **SC-001**：三种平台选择均生成恰好相应的独立构建定义；已有文件、重复／未知选择、冲突选项全部拒绝且文件不变；预览外部动作及密钥读取次数为零。
- **SC-002**：已安装、缺失、不可执行、错误版本及取消五类真实环境检查均给出对应状态，所选平台之外的缺失项不阻塞有效检查，未提供签名不会冒称签名通过。
- **SC-003**：同一真实工程在两个真实操作系统环境产出 Android 发布／安装包，并在授权环境产出 iOS 签名安装包及归档／符号；默认和至少一个非默认变体的身份、版本、编号、签名、大小和摘要全部符合声明。
- **SC-004**：编辑模板增加的仓库脚本实际消费至少 version、channel、flavor 三项参数；未知／非法参数、错误工具／签名、错版本和缺失应有产物均不能返回完整成功结论。

- **SC-006**：授权真实节点能执行并下载完整双平台证据；缺少所需能力或授权的节点不领取，过期／撤销／保存失败不继续用户动作或补报成功，下载大小／摘要与原快照一致。
