# 001 技术研究

- 决定：遵循既有选型使用 go.yaml.in/yaml/v3，锁定可获取的 v3.0.5；不改用新 major，也不引入第二套解析库。
- 理由：标准库没有 YAML；该库维护已有 v3 API。使用 Node 先检查类型/重复/未知字段及边界，再解码；不能依赖解码到 string 自动保证标量类型。
- 备选：仅 KnownFields 对自定义解码与标量转换不够；动态通用 map 会弱化结构；手写 YAML 解析不采用。
- 安全：不原样返回第三方解析错误，避免包含凭据标量；输出位置和固定原因。拒绝 alias/merge/null 与多文档，有限递归验证。
- 预览：纯函数接收运行事实，当前 CLI 不搜集 Git/密钥；所有参数值与脚本正文隐藏，条件仍按内部已校验值计算。
- 来源：[YAML v3 官方 API](https://pkg.go.dev/go.yaml.in/yaml/v3)，已核实本地 v3.0.5 源码；研究代理已核对：KnownFields 对 Node 无效；string 自动转换标量；安全错误须自建。AST 后才执行深度/节点限额，不宣称库会在第 33 层停止解析。
