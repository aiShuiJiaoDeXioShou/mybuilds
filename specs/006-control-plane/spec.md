# 功能规范：006 控制端与持久化队列

**Feature Branch**: `006-control-plane`
**Created**: 2026-10-04
**Status**: 已实现并验收，收敛无缺口
**Input**: 已授权的全部MVP目标，按产品专题交付控制端配置、双数据库、唯一控制端、项目组、身份鉴权、固定提交快照、原子排队、远程API及CLI。前置已验收003/004（2ab8991），执行依赖修正见MVP_EXECUTION；本功能不执行构建，不借用005未验收代码。

## User Scenarios & Testing

### User Story 1 - 初始化一个可独占运行的控制端 (Priority: P1)
管理员按服务端配置启动控制端，选择默认数据库或已有数据库，初始化管理员身份；配置错误、数据库异常和第二控制端启动明确失败，不启动构建脚本。
**Why this priority**: 持久化与单控制端是后续项目管理和多节点执行基础。
**Independent Test**: 在独立临时数据目录及独立数据库启动真实服务，健康查询、重启与第二进程竞争。
**Acceptance Scenarios**:
1. 给定合法默认配置，启动与重启后组、项目、身份及排队记录保持。
2. 同一数据库已有控制端，第二进程被拒；原服务关闭后新进程可启动；锁丢失停止新业务授权。
3. 未知字段、非法类型/地址/并发/数据库或配置中的机密标记，启动失败且输出不回显机密。

### User Story 2 - 注册项目并管理项目组 (Priority: P1)
管理员使用客户端或控制端本机命令创建组、登记可信仓库、选择组或默认组，修改流水线路径和组归属，查询历史。
**Why this priority**: 项目身份与构建号独立于分组，防止迁移导致历史丢失。
**Independent Test**: 两种数据库运行同样的创建、改名、迁移、并发删除和历史查询行为。
**Acceptance Scenarios**:
1. 未指定组进入default；目标不存在拒绝且不改变项目。default不可改名或删除，普通组名称唯一、只允许删除空组。
2. 组改名、项目迁移保持项目ID、配置、构建号及历史；迁移当前组成功且不产生虚假变更审计。
3. 本机与远程入口使用同样规则；--settings相对客户端当前目录读取后导入，--file保存仓库相对路径，不混用。

### User Story 3 - 安全触发并原子保存固定提交的多build (Priority: P1)
有权限的客户端选择一个可信项目、授权分支、命名build和参数；控制端读取固定提交的流水线并校验整批，不执行仓库命令，然后返回可查询的独立任务。
**Why this priority**: 固定来源、原子入队和幂等构建号是远程执行的正确性基础。
**Independent Test**: 自有真实Git仓库包含多个提交/build；并发请求、分支变化和非法参数验证快照与编号。
**Acceptance Scenarios**:
1. 选择多个build固定一个SHA；每个有效任务获得独立ID和项目共享的不同构建号；一个参数/定义/权限错误时整批不入队、计数器不变。
2. build.when分支/参数不匹配记录skipped，无编号/节点；手动触发忽略changes并记录理由，不将尚未解析的模板上下文当成执行许可。
3. 分支推进后同身份同幂等键同原请求仍返回原批次/编号；不同内容复用键冲突；并发重试只提交一批。
4. 指定ref须属于授权分支；配置缺失/非法/越界、读取失败或不可信ref拒绝，不能退到分支最新提交或修改用户工作树。

### User Story 4 - 独立身份与可查询的队列证据 (Priority: P1)
管理员管理token；触发身份只能触发非发布构建及基本服务状态，审批身份能读取授权范围的构建证据，管理员可管理全部。客户端查询排队、条件原因、预算与进度，无需节点在线。
**Why this priority**: 身份边界及持久化证据必须先于执行和发布。
**Independent Test**: 真实HTTP请求覆盖无凭据、错误/撤销身份、三角色和一次性初始化；检查公开结果与存储的敏感边界。
**Acceptance Scenarios**:
1. token创建只显示一次，列表及数据库不保存明文；已初始化后撤销全部身份不重新创建bootstrap身份。
2. trigger身份不能管理项目/组、读取敏感详情或触发含upload的所选定义（不因when未满足绕过）；admin需显式allow_upload才能排队发布定义，排队并不授权实际上传。
3. 构建列表支持项目/当前组/build/批次/状态及有界分页；详情保留来源摘要、条件事实、初始化预算和ordinary/post进度，公开输出不展示配置正文/参数值/凭据。

### Edge Cases
- 空/重复build选择、单build省略选择、多build未显式选择、全skipped、混合skipped与queued、整数构建号溢出。
- 同时迁移/删除组、并发触发、同key不同身份、Git取值期间分支推进、数据库事务失败。
- 配置缺失与显式指定不存在的配置、相对路径/tilde、机密文件权限、HTTP超限/未知字段/多JSON对象。
- 未声明runner且没有default_node、default_node不属于授权集合、尚无注册节点的排队。
- 仓库文件是symlink/非普通文件、配置正文含凭据引用和攻击性shell；控制端只读取，不执行或解析节点密钥。
- 控制端关闭或锁丢失与写请求竞态；SQLite路径别名、PostgreSQL同数据库不同DSN的独占竞争。

## Requirements

### Functional Requirements
- **FR-001**: 服务端配置支持默认值、文件、明确的环境变量与CLI覆盖；未知/重复/null/非法类型或值拒绝；相对路径基于配置文件目录，~展开；机密错误固定脱敏。
- **FR-002**: 控制端持久化支持两种既定数据库，同一组项目/组/身份/批次/任务/编号/幂等/条件更新/分页行为一致；切配置不迁移数据。
- **FR-003**: 同一数据库仅一个控制端可持有运行权，启动和本机写管理命令均需独占；锁丢失或无法确认时停止新写业务和授权，优雅关闭释放资源。
- **FR-004**: 初始化固定default组；普通组创建/列表/改名/删除具名称唯一和空组检查，default不可删除改名，数据库约束保护并发归属。
- **FR-005**: 项目全局名称唯一，登记可信仓库、provider、授权分支、允许节点名、default_node、正初始构建号及仓库相对流水线路径；default_node须在允许集合，节点匹配在007进行。
- **FR-006**: 项目未选组进入default，迁移只改归属并保存身份/时间/原目标审计；项目ID、历史、配置和编号不变；查询按当前组过滤。
- **FR-007**: 客户端读取本地settings后导入，file为仓库相对路径，二者互斥；本阶段只支持auto/repo仓库来源且auto无文件明确失败，绑定方案/profile/framework选项明确报尚未支持，012再接入。
- **FR-008**: token随机高熵，只保存摘要/身份/角色/撤销状态，创建仅显示一次；bootstrap只在首次身份初始化时从明确环境值使用，撤销后不自动重建；服务端普通配置不存token明文；客户端仅允许受限0600文件中的明确token字面量或完整环境引用/环境覆盖，token不进入公开输出。
- **FR-009**: API统一鉴权，admin可管理与读写；trigger只允许基本状态及所选定义不含upload的触发（权限先于when判定）；approver可读全部脱敏build列表/详情作为审批证据但不可管理/触发，实际审批014接入。跨主机必须验证HTTPS证书，不提供跳过验证。
- **FR-010**: 触发指定授权分支并固定完整SHA；显式ref必须可达，拒绝tag/其他分支越权和隐式回退；通过只读Git读取该提交的普通流水线文件，不执行仓库shell、不改变用户工作树。
- **FR-011**: 复用严格解析、build选择、参数校验及模板检查；远程支持共享参数与build限定参数，命名覆盖优先，拒绝未选build/未知参数；project身份/编号/SHA等系统事实不能被参数伪造。
- **FR-012**: 全批配置、参数、权限、runner/default_node和发布显式许可检查成功后（所选build含upload无论when是否满足都要求admin+allow_upload），按build.when分支/参数判定，手动changes豁免；冻结所有条件事实及原因，未就绪的执行上下文留给节点，不误判build.when。
- **FR-013**: 一次事务创建批次和所有独立结果，queued按项目共享计数器原子分配正编号，skipped无编号或节点；任何失败回滚全部结果、计数器和幂等记录。
- **FR-014**: 触发携带按身份作用域唯一的幂等键，先按原请求查键再读取Git；相同内容返回原结果，不同内容冲突，事务内再次核对唯一键处理并发，不在事务内执行Git/shell/network。
- **FR-015**: 执行快照保存选定定义、固定SHA、来源/摘要、参数与节点密钥引用、条件事实及原因，不解析节点凭据；创建ordinary/post步骤进度和累计剩余预算，恢复查询不重置；敏感配置正文与参数不在公开输出回显。
- **FR-016**: 项目/构建列表与详情、status提供有界分页和稳定顺序，项目/组过滤取交集，批次记录每build独立状态/编号；无节点阶段任务保持queued，不冒充执行成功。
- **FR-017**: 服务端serve/migrate/project/group/token、本机管理与客户端project/group/trigger/build ls/show/status按相同业务规则工作；本地init/run/doctor/version/help不要求控制端配置或token。
- **FR-018**: 请求体/字段/名称/路径/参数/分页/Git输出/超时均有界，重复字段/未知字段/多对象拒绝，响应及日志不得回显敏感输入、仓库URL中的凭据或底层数据库/Git错误。
- **FR-019**: 本功能不执行用户shell、分配节点租约或上传；Agent/日志/产物远程闭环007、恢复008、发布010/011、方案012、审批014、Webhook015、报告019与retention020维持独立验收。尚未支持的设置明确拒绝，不静默启用。
- **FR-020**: 功能规范/计划/任务/真实验证、README和历史同步；全量检查、双数据库、真实Git/API/CLI与收敛通过后整功能一次本地提交。005待真实签名状态与其验收标准不改变。

### Key Entities
- 项目组与项目：稳定ID、当前归属、管理策略、统一计数器。
- 用户身份：随机token摘要、角色、撤销与初始化记录。
- 触发请求与批次：身份+幂等键+原请求摘要、固定提交与结果集合。
- 执行：命名build、编号或skipped、配置/条件/参数快照、初始化预算与步骤/post进度。
- 管理审计：项目迁移、组改名和身份操作的执行者、UTC时间与对象。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 两种数据库均通过同样的项目组、迁移、身份、事务回滚、编号唯一、幂等与分页验收，实际重启保留全部记录。
- **SC-002**: 两个真实进程竞争同一数据库时只有一个取得控制端运行权；正常关闭可再启动，锁失效不能继续写业务。
- **SC-003**: 20个并发相同请求只产生一批结果；20个不同请求取得不重复编号；无效整批请求与全skipped不消耗编号。
- **SC-004**: 自有真实Git仓库分支推进后，首次结果及同key重试的SHA/快照/参数/条件/编号不变；不可达ref与坏配置均无入队或shell副作用。
- **SC-005**: 真实客户端完成初始化控制端连接、创建组/项目、触发和查询；三种身份权限、撤销和一次性bootstrap、配置与请求负例均可执行验证且不泄密。
- **SC-006**: 所有功能任务与收敛缺口闭合，必要检查及双数据库证据通过；服务仍明确仅排队，无节点执行、发布或iOS签名验收的虚假声明。

## Assumptions

- 管理员仅登记可信仓库/分支；控制端Git只读凭据在控制端，节点签名与发布凭据留在节点。
- 允许节点名可以先配置，在007只匹配已注册且获授权的健康节点；此阶段不注册Agent、不授执行权。
- 自动配置仅尝试仓库文件，缺失明确失败；profile/绑定方案、通知、自动触发、保留策略的业务接入留给对应功能，不丢弃或假装已生效。
- 单控制端、两个CLI与已有pipeline，不新增插件、通用repository、消息队列或WebUI。
- 本机具备真实Git及独立临时PostgreSQL环境，可自行创建测试夹具；不连接或修改用户已有数据库。跨平台客户端编译与服务端macOS/Linux约束保留。
- iOS签名真实材料属于005/009及005+007联验条件，不是控制端读取配置/排队的依赖；006不接受本基线未知ios_signing字段，后续005集成再复验快照往返。
