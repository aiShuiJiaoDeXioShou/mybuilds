# 功能规范：产物快照与本地结果

**Feature Branch**: `003-build-artifacts`
**Created**: 2026-10-04
**Status**: 已实现并验收
**Input**: 接续已验收002，交付递归glob产物收集、路径边界、独立快照和可核对的清单；补齐产品P1本地结果目录与按步骤日志保存。

## User Scenarios & Testing

### User Story 1 - 收集构建结果（Priority: P1）
开发者在脚本之后收集仓库文件，找到真实本地副本并核对摘要。
**Why this priority**: 为平台构建与后续发布提供可靠文件证据。
**Independent Test**: 真实脚本生成嵌套文件，收集后清单大小/摘要与副本一致。
**Acceptance Scenarios**:
1. paths始终相对工作区根，支持**零层/多层，模板和条件复用既有规则。
2. 每个模式至少匹配一个合法文件；重叠去重，同basename不同路径保留。
3. 生效artifact可单独执行，不要求前一步run；匹配失败停止当前build而其他build可继续。

### User Story 2 - 安全保存原证据（Priority: P1）
开发者不希望收集越界文件、特殊文件或半写结果，post修改也不能覆盖原副本。
**Why this priority**: 后续审批/发布必须引用明确且完整的产物。
**Independent Test**: 链接/取消/复制失败被拒绝，post重写源文件后普通步骤原副本和摘要仍不变。
**Acceptance Scenarios**:
1. 根内相对普通文件链接可收集；越界/绝对/悬空链接与特殊文件拒绝，目录不作产物。
2. 通配遍历不跟随目录链接；字面前缀中的根内相对目录链接允许，递归链接不造成循环。
3. 复制在独立临时目录完成后原子发布清单，失败不留下可见部分产物；每步/普通与post保留独立副本。
4. 收集与复制受取消及当前步骤/build/post剩余预算约束，不无限遍历或复制；源文件读期间变化拒绝。

### User Story 3 - 查询本地证据（Priority: P2）
开发者通过JSON找到保存目录、每步脱敏日志和产物，失败后也能诊断。
**Why this priority**: 本地执行需要可定位的输出文件，不能只在终端显示。
**Independent Test**: 二进制执行后读取每步日志文件和产物清单，secret未出现且下载副本可核对。
**Acceptance Scenarios**:
1. 全批预检查通过且存在选中生效步骤后创建受限临时结果目录，JSON返回位置；dry-run/预检查失败/全部跳过不创建。
2. 每步保存与终端一致的UTC脱敏日志，两流可辨；失败/取消结果也保留，用户工作树不放入结果数据。
3. 文件写入/关闭失败明确失败且安全诊断，不覆盖原执行失败/取消原因。

### Edge Cases
- **零层嵌套、重叠模式、同名文件、目录链接环、字面目录链接和空目录。
- 绝对/..路径、非法模式、非普通文件、符号链接换目标、取消时遍历或复制。
- 源文件被改写、post重复源路径、原命令失败后的诊断artifact、本次日志写失败。
- --step独立收集、全部跳过、后续build预检查失败不创建结果目录。

## Requirements

### Functional Requirements
- **FR-001**: 收集artifact.paths相对仓库根，递归glob支持**，所有渲染模式先整批严格校验，when规则与普通步骤一致。
- **FR-002**: 每模式独立验证至少一个合法普通文件，跨模式按相对路径去重并稳定排序，同basename不冲突。
- **FR-003**: 实际文件访问受仓库根约束，拒绝越界/绝对/悬空链接和特殊文件；目录不收集，不跟随通配匹配中的目录链接。
- **FR-004**: 允许字面路径前缀根内相对目录链接及根内相对普通文件链接；所有实际访问仍受根约束，链接环不能无限遍历。
- **FR-005**: 将原文件复制到独立步骤快照，记录源相对路径、快照相对路径、实际字节数和SHA-256；读期间源身份/大小/修改时间变化拒绝。
- **FR-006**: 一次artifact全部临时副本完成才原子发布可见清单；失败/取消删除本次临时副本，不覆盖其他步骤证据或用户文件。
- **FR-007**: 普通与post每个artifact使用独立快照，post源修改不能改变普通步骤证据；原失败后仍可收集诊断产物。
- **FR-008**: 遍历与复制响应取消/剩余执行预算，artifact耗时累计进build或post预算；失败处理沿用002。
- **FR-009**: --step可仅执行一个artifact，仍整批校验；artifact确实开始处理计作已开始执行，才能按原结果运行post。
- **FR-010**: 预检查成功且有选中生效步骤后创建本地受限临时结果目录，结果JSON返回绝对位置；预览/预检查失败/全跳过不创建。
- **FR-011**: 每普通/post步骤保存UTC脱敏日志，两流来源明确，与终端相同；文件权限受限、关闭受控，不将运行数据放入源码工作树。
- **FR-012**: 输出保存错误不泄露底层错误或密钥，使原成功失败但保留原失败/取消证据；失败也可查已有完整日志/快照。
- **FR-013**: 生效upload/approval/reports/notifications仍明确未支持，预览无副作用、既有shell/取消/预算/post与CLI保持。

### Key Entities
- 产物记录：源路径、独立快照路径、大小和SHA-256，属于本次build/步骤。
- 本地结果目录：受限临时目录，每步日志与快照，生命周期由用户本地管理。
- 产物步骤结果：状态、耗时、固定原因、零或多产物记录；错误时不返回部分清单。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 真实嵌套构建文件、**、重叠和同名场景正确，所有清单可核对副本字节/大小/摘要。
- **SC-002**: 越界/非法链接/特殊文件/零匹配/取消/复制失败拒绝，不留可见部分产物，不更改用户文件。
- **SC-003**: post重写同源文件后普通快照与摘要仍正确，原失败诊断可用，预算与取消行为保持。
- **SC-004**: JSON位置可定位，按步骤日志存在且无声明secret，dry-run/预检查失败/全跳过无结果目录。
- **SC-005**: 全量既有行为通过，真实二进制run收集和Windows/Linux客户端可编译，未交付能力不降级。

## Assumptions
- 前置002验收提交256af8e。产物为文件，不把目录当作文件；无可下载的中央服务或产物管理CLI在本功能冒充实现。
- 本地结果保存系统临时目录，权限0700/0600，不自动删除已完成结果；每次运行新目录，使用JSON给出位置。
- 目录通配遍历不跟随目录链接，字面前缀链接允许根内相对访问；每模式零合法匹配失败，固定规则无需额外用户开关。
- 可信脚本执行不是沙箱；只承诺根约束文件访问、源变化检测与独立快照，不保证任意恶意脚本或同用户外部进程不能修改结果。
