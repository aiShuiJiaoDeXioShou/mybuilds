**Feature Branch**: `020-project-retention`
**Created**: 2026-10-04
**Status**: 规范完成；008与019正式前置已验收，设计/任务校正与分析完成，Foundation实施中，未整功能验收
**Input**: 依据 PLAN、SPECKIT_ROADMAP、MVP_EXECUTION、CONFIGURATION 保留策略专题和 MULTI_NODE：项目按字段继承全局数量/天数，跨命名 build 筛选终态；保护活动、审批、停止未确认、上传 unknown 和下载；删除前复核，中央与原节点受限幂等清理，离线保持待确认，保留编号及必要审计。已有spec/plan/tasks，按已验收008/019正式校正后analyze与implement，不修改原25FR/7SC/16AC。

## User Scenarios & Testing

### User Story 1 - 管理项目的有效保留策略 (Priority: P1)

管理员统一设置全局保留数量与天数，也可为某个项目只覆盖其中一个字段。查询时能分辨有效值及其来源，项目迁移分组不改变其身份与独立策略，仓库内容不能扩大清理权限。

**Why this priority**: 清理必须遵从明确的管理员策略，避免部分设置意外覆盖另一个维度。

**Independent Test**: 用两个项目设置全局值、完整覆盖、单字段覆盖和恢复继承，检查有效值；非法设置与无权限提交不改变已有策略。

**Acceptance Scenarios**:

1. **Given** 全局数量100、天数30，**When** 项目只设置数量200后全局天数改为45，**Then** 该项目有效值为200/45，另一个未覆盖项目继承100/45；清空该项目的覆盖块恢复两字段继承。
2. **Given** 合法已有策略，**When** 提交0、负数、小数、字符串、null、未知/重复字段或仓库内的管理策略，**Then** 明确拒绝，无策略变更或文件删除。
3. **Given** 触发身份、审批身份或节点身份，**When** 尝试修改策略或发起管理清理，**Then** 明确拒绝；管理员成功设置有必要审计，不公开凭据。

### User Story 2 - 按项目筛选历史并保留受保护证据 (Priority: P1)

管理员希望清理过旧或超量的完整构建历史，不因 build 名称、分组迁移或停止确认重新开始保留期限；任何仍用于执行、审批、结果确认的证据必须保留。

**Why this priority**: 错删原产物、未知执行或发布证据会破坏恢复、审批和审计。

**Independent Test**: 同项目多个命名 build 与另一个项目具有受控完成时间，运行一次策略评估及清理；核对候选集合、保护原因、边界与实际保留内容。

**Acceptance Scenarios**:

1. **Given** 同项目两个命名 build 共6条有可信终态时间的记录，数量限额4且全部未超天数，**When** 清理，**Then** 按项目汇总保留最近4条、选中较旧2条，不按 build 分别保留4条；另一个项目不受影响，活动记录不占终态配额。
2. **Given** 数量限额内有一条完成时间严格早于天数边界的终态记录，**When** 清理，**Then** 它仍是候选；恰等于边界或排名等于数量限额不因该维度入选，同完成时间有稳定排序。
3. **Given** 超限记录分别处于 queued、running、waiting_approval、stop_unconfirmed、上传unknown、尚有未确认动作/资源或实际下载中，**When** 评估及删除前复核，**Then** 全部保留实际文件，明确保护原因；业务保护存在时不退役供后续恢复的引用；停止确认不解除上传unknown保护，下载保护按下一故事的退役/等待读取流程处理。
4. **Given** 记录已成为候选，**When** 删除前保护状态、策略或对象归属改变，**Then** 按当前事实重新判定；已不符合条件或无法证明安全时不删除，不把旧候选视作持续授权。
5. **Given** queued取消、创建即skipped、中断后持停止保护、以及缺少可信终态时间的旧记录，**When** 排序和停止保护解除，**Then** 使用真正进入终态的时间；解除保护不刷新完成时间，旧记录不借任意更新时间参与删除。

### User Story 3 - 中央与原节点分别安全完成清理 (Priority: P1)

管理员能看到中央文件和节点工作区各自的待清理、等待、失败与完成结果。节点离线不妨碍持久保存待清理事项，也不能被中央“删除成功”冒充原工作区已删除。

**Why this priority**: 文件删除和远端确认存在中断与竞态，必须防止半途删下载、越界删用户文件或失联后丢任务。

**Independent Test**: 真正中央与Agent进程持有自有日志、二进制产物、测试原始报告及工作区，组合已有下载、离线、重启、回执丢失和文件边界负例。

**Acceptance Scenarios**:

1. **Given** 候选构建的二进制产物或原始报告正被下载，**When** 中央开始退役其文件引用，**Then** 拒绝新下载但已有读取完整结束，原文件不被截断/替换/半途删除；已有读取结束或明确终止后重新复核，才可删除。日志读取同样保护实际占用文件。
2. **Given** 中央已保存清理意图并删除部分文件，**When** 控制端关闭、重启或删除失败，**Then** 恢复同一清理记录，实际未删部分仍显示待处理/失败，不发布虚假完成，不启动任何构建、收尾或上传动作。
3. **Given** 原节点离线，**When** 中央清理可删除的中央副本，随后该节点使用当前独立身份重连，**Then** 原工作区仍是待清理，节点获得绑定自己的同一删除事项；实际删除后确认，已不存在的已知目标和重复同内容确认均幂等成功。
4. **Given** 一个有效删除事项，**When** 另一节点、撤销身份、冲突回执或任意路径请求尝试使用它，**Then** 拒绝；对符号链接、特殊文件、目录替换、越界路径和未登记文件不跟随或扩大删除范围，周边自有对照文件保持原样。
5. **Given** 节点本地仍有活动进程、未确认执行日志或不能证明目标归属，**When** 领取或执行工作区删除，**Then** 节点拒绝并报告固定安全原因，控制端保留待清理/失败，不凭旧终态执行租约强制删除。

### User Story 4 - 查询结果并保留编号、幂等与必要审计 (Priority: P2)

管理员能解释为何历史被清理或暂时保留，清理不能把项目当成全新项目，也不能让旧触发请求重新创建执行。

**Why this priority**: 释放空间不应损害原请求身份、构建号连续性与必要操作追溯。

**Independent Test**: 清理自有项目历史后查询清理结果、重放原触发键及触发新任务，检查真实编号、对象数量与脱敏审计。

**Acceptance Scenarios**:

1. **Given** 一个项目曾分配至编号101且其完整历史已符合清理条件，**When** 清理后重放原同身份同请求键，再触发新任务，**Then** 重放仍对应原批次/执行/编号，不执行或新分配编号；新任务继续原计数器，组迁移与历史清理均不重置。
2. **Given** 某中央删除失败、节点待确认或对象已完成清理，**When** 管理员查询，**Then** 能区分对象、结果、保护/固定失败原因和时间；已清理正文/文件明确不可读取，审计不含原始日志、参数、脚本、凭据或任意系统路径。
3. **Given** 后续审批、发布unknown等功能真正产生受保护证据，**When** 与本策略联验并解除各自保护，**Then** 实际保护期间不删除；仅解除停止保护不能清理unknown，保护全部解除后才可再次按原完成时间评估。

### Edge Cases

- 多命名 build、无编号skipped、无节点终态、queued取消、同时间并列、恰等于数量/天数边界；项目与组改名/迁移不改变计数范围。
- 中断记录先受停止保护，随后真实停止确认；unknown人工确认与停止确认相互独立；无法证明终态时间或清理对象归属时保守保留。
- 策略更新、审批恢复、未知结果确认、读取开始与候选/删除竞态；下载断流、取消或读取超时必须释放真实占用，不无限持有已不存在的读者。
- 控制端在意图保存、引用退役、文件删除或结果确认之间关闭；第二控制端无运行权不能授权清理；文件与记录部分完成不假装全完成。
- 节点离线、凭据轮换/撤销、节点墓碑、回执丢失、重复/冲突确认、重复领取；节点无法重连时一直保留未完成事项，不偷偷改派其他节点。
- 文件不存在、权限拒绝、特殊文件、符号链接/硬链接、父目录或目标替换、相对路径越界；未知孤立文件及共享工具缓存不属于本策略扫描删除目标。

## Requirements

### Functional Requirements

- **FR-001**: 支持全局与项目 retention 的 builds/days 正整数设置；未知、重复、null、错误类型、非正或超出可表示范围的值在生效前拒绝。内置默认100条/30天，明确为本规范选定默认，而非声称产品示例具有硬约束。
- **FR-002**: 项目按字段覆盖全局；省略字段继承当前全局有效值，省略/空覆盖块继承两字段。管理员能查询有效值及其来源；组迁移不改变项目覆盖。
- **FR-003**: 管理策略仅由管理员从管理配置/项目设置导入或更新，仓库流水线、构建参数、节点报告不能改写；错误或无权限提交不部分变更策略，不触发删除。
- **FR-004**: 数量按同一项目全部命名 build 的完整终态历史汇总，包括无编号skipped；活动记录不挤占终态配额。已有可信终态时间的保护记录仍参与排序，但保护优先、实际保留数可超过限额；已清理的最小证据不重复占历史配额。
- **FR-005**: 以持久的真正终态时间从新到旧排序，同时间以稳定执行ID排序；超过最近N条或严格早于评估时刻减D个24小时的UTC时间边界即为候选，两维度为OR。排名N及时间等于边界不因该维度删除，其他维度与保护仍分别判断。
- **FR-006**: 明确保存正常完成、queued取消、创建即skipped和中断进入终态的真实时间；停止确认、结果确认、策略变更、重放、清理及一般更新不重置它。既有记录只有可证明的终态发生依据才能补齐；缺少依据的记录标记时间待确认，保护且不进入按时间排序的配额，不把任意更新时间冒充完成时间。
- **FR-007**: queued、running、waiting_approval、停止未确认、上传结果unknown、存在未确认执行/系统资源和实际文件读取的构建必须保护其实际文件与必要证据，无论数量、年龄、失败/取消状态或策略如何；可分别展示多个保护原因。业务保护存在时不得退役恢复所需引用；只有读取占用时可按FR-011退役新引用并等待，但仍禁止物理删除。
- **FR-008**: 本功能不确认停止、审批、上传结果或未知执行，不因retention自动解除互斥、隔离或应用锁；只有既定流程确认保护事实解除后，才能重新评估。节点失联/租约过期不是物理停止证据。
- **FR-009**: 候选不是删除授权；中央在每次实际退役/删除前重新确认当前有效策略、构建/文件归属、保护状态和控制端运行权，无法证明安全时不删。节点领取授权及执行删除前同样复核，不凭旧候选或过期执行租约继续。
- **FR-010**: 策略覆盖中央历史正文、日志、普通/post产物、测试原始报告及其摘要和登记的节点工作区/本次结果文件；封存审批或发布证据受相同保护，不遗漏post诊断副本或原始报告。
- **FR-011**: 中央实际删除前必须持久保存清理对象与意图；业务保护均已解除时可先退役受影响文件引用、拒绝新读取；若只有现有读取占用，则等待已有读取完成或明确终止并复核，才能删除。退役等待不宣称完成；已有下载/日志读取的数据不可被截断、替换或半途删除。
- **FR-012**: 读取结束、取消、断流、超时及控制端关闭必须有可确认的占用释放；重启核对实际读者和清理状态，不能用过期的“正在下载”记录永久假占用，也不能无证据假定旧读者已结束。
- **FR-013**: 中央只删除本控制端管理目录内、清理记录明确归属的对象；不接受请求中的任意路径，不跟随链接越界，防止对象/父目录替换扩大范围。不存在目标、权限错误与类型/归属不明分别处理，只有已知目标确实不存在可视为该对象已删除。
- **FR-014**: 节点工作区清理必须使用当前独立节点身份下的专用管理事项，绑定节点、删除ID与工作区/原执行身份；不复用终态或过期构建租约，不转交其它节点，不授予用户脚本执行权。
- **FR-015**: Agent 删除前确认本地无活动进程、未确认执行/签名资源或未知日志，目标是自己登记且位于data_dir内的工作区/结果对象；任意路径、符号链接/硬链接、特殊文件、替换、未知对象与归属不明均固定安全拒绝，不杀无关进程或删除用户工程。
- **FR-016**: 离线、撤销身份或无法安全确认的节点保持持久待清理/失败；凭据轮换后同一原节点可用当前合法身份继续同一事项。节点墓碑或永久离线不产生虚假确认，中央副本完成与节点完成分别记录。
- **FR-017**: 同一删除ID的重复领取、已知目标已不存在、相同确认内容均幂等；不同节点/对象或冲突确认明确拒绝。确认响应丢失不生成新删除身份，只有真实删除回执得到确认后才标节点完成。
- **FR-018**: 控制端/Agent重启、文件与记录部分完成、回执或网络失败后恢复原清理事项，不能重新运行构建/收尾/上传；保留未完成对象及固定失败原因，后续可安全重试同一删除，不把失败当成不存在。
- **FR-019**: 保留项目计数器、必要操作与清理审计，以及原身份作用域的触发请求幂等和编号最小证据；清理后相同键同请求仍返回原批次/执行/编号关系，不再执行或新分配编号，冲突键仍拒绝，新请求继续原计数器。
- **FR-020**: 管理员可有界查询有效策略、受保护/候选/待清理/失败/完成结果和必要审计；已清理的正文、文件明确不可再读取，不伪装空成功。公开结果不回显脚本、参数、原始日志、密钥、凭据引用值或底层系统错误/任意路径。
- **FR-021**: 沿用用户与节点独立身份边界：只有管理员改变/启动管理清理并查看清理审计；trigger/approver不能删除，节点只能领取/确认自己事项。原有基本状态查询与授权证据读取行为保持，读取已退役文件明确失败。
- **FR-022**: 后台清理及查询批量、执行等待、网络和输入必须有界；停止控制端运行权或身份失效后不产生新的删除授权，已进行的对象操作保留真实结果与恢复依据，不以固定计时器冒充完成。
- **FR-023**: 不清理数据库、管理员凭据、共享SDK/工具缓存、未登记孤立文件、源码工作树或本地独立run的结果目录；不提供绕过保护的force删除，不预建通用缓存/垃圾收集平台。
- **FR-024**: 必须在008恢复与019报告验收集成后才进入本功能后续实施；使用其真正状态、身份、报告和对象登记。020可先于发布/审批功能，但这些功能后续联验须用实际产生的审批/unknown状态验证保护，不以手改状态或仅文档宣称取代最终联验。
- **FR-025**: 两种既定数据库运行同一清理/保护/幂等/恢复行为，macOS/Linux真正中央与Agent及客户端闭环覆盖下载、重启、离线与受限目录删除；保留既定单控制端与跨平台远程CLI边界，不用交叉编译或模拟执行替代实际门。

### Key Entities

- **有效保留策略**：全局数量/天数、项目逐字段覆盖和来源，按稳定项目身份生效。
- **终态历史与保护事实**：命名build、原编号、可信终态时间、读取占用、活动/审批/停止/unknown等保护；同一执行可能同时受多种保护。
- **清理事项**：稳定删除身份、原项目/构建/文件或工作区归属、策略判定与复核时间、中央及节点分别的结果、固定失败原因。
- **节点确认**：当前独立身份、原节点与明确工作区归属、真实删除结果、幂等确认关系。
- **最小保留证据**：项目计数器、原请求/批次/执行/编号关系和必要清理审计，不保留已经删除的正文/日志作为公开查询内容。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 全局、单字段项目覆盖、两字段覆盖和恢复继承的验收结果全部准确；每种非法或无权限变更均保持原策略与文件不变。
- **SC-002**: 跨命名build、多项目、数量/天数OR、同时间、精确边界、无编号终态与可信终态时间的固定验收集合，候选/保留结果100%符合规则，组迁移不改变集合。
- **SC-003**: 每种活动、审批、停止未确认、unknown、资源未确认和旧时间不明保护，以及候选后新增保护的竞态用例中，误删数量为0；必要证据保持可核对。
- **SC-004**: 实际二进制产物、原始报告和日志读取与清理竞争时，已有读取完整结束或明确终止，成功下载摘要和预期完全一致，退役后新读取均不能获取对象。
