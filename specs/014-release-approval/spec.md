# Feature Specification：发布审批与原节点检查点恢复

**Feature Branch**：`014-release-approval-planning`

**Created**：2026-10-05

**Status**：已实施；必要自动验证见validation，合法材料与完整人工矩阵待用户验收。

**Input**：用户已授权全MVP；依据产品计划的CLI发布审批、检查点释放容量、原节点恢复、冻结证据与累计预算；本地构建调试支持明确交互确认，不依赖通知。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全挂起并查看原构建证据（Priority: P1）

构建到审批步骤后，审批人查看这次构建实际完成的产物与测试；等待不会占住构建机器的执行容量。

**Why this priority**：审批必须指向已完成的真实成果，且等待不妨碍其它构建。

**Independent Test**：运行有真实产物/报告的构建，在审批处停止，查看证据并让同节点另一命名构建执行。

**Acceptance Scenarios**：

1. **Given** 前置步骤真实完成且配置要求的报告通过，**When** 到达生效审批，**Then** 封存原证据、剩余预算与准确检查点，确认本次进程停止及临时签名资源已清理后才进入待审批并释放执行容量。
2. **Given** 一个构建正在待审批，**When** 触发同项目同名构建及不同命名构建，**Then** 原同名互斥保持，不同构建可按真实容量正常执行。
3. **Given** 检查点尚未完整保存或停止/资源清理未知，**When** 连接丢失或控制端重启，**Then** 不展示可安全放行的待审批，不错误释放保护，不重跑旧动作。
4. **Given** 原检查点已持久保存，**When** 任一端重启且审批尚未决定，**Then** 原归属、封存证据与剩余预算保持，不自动批准或继续。

### User Story 2 - 有权限的人作出唯一审批决定（Priority: P1）

审批人列出待审批构建，明确批准或拒绝并保留身份、时间和意见。

**Why this priority**：发布授权必须有可核对的决定，网络重发不能产生相反或重复决定。

**Independent Test**：以管理员、审批者、触发者及节点身份实际调用列表和决定入口，检查并发/重复/冲突。

**Acceptance Scenarios**：

1. **Given** 构建已安全待审批，**When** approver或admin明确批准当前审批，**Then** 保存该次决定及审计，并进入仅原节点可恢复的等待状态。
2. **Given** 已安全待审批，**When** 合法审批人拒绝，**Then** 构建为cancelled/approval_rejected，封存历史保留，不启动用户收尾或上传。
3. **Given** 同一决定响应丢失，**When** 对精确同一审批重发相同决定，**Then** 返回原决定；不同决定、过时审批或不同意见冲突不覆盖原决定。
4. **Given** 触发者、节点凭据、无效身份或只读请求，**When** 尝试决定，**Then** 拒绝且无状态/预算/审计决定变化；公开列表和详情不泄露机密。

### User Story 3 - 在原节点复核后继续原构建（Priority: P1）

批准后继续这次构建尚未执行的部分，使用原工作区、原产物和原剩余预算。

**Why this priority**：审批不能变成新构建、重做测试或使用审核后修改的产物。

**Independent Test**：批准后竞争领取，分别改变原节点授权、工作区与证据，并核对合法恢复只继续下一步骤一次。

**Acceptance Scenarios**：

1. **Given** 原检查点批准且原节点健康、有容量和当前权限，**When** 原节点领取恢复，**Then** 同一构建号/提交/执行历史继续下一未执行步骤，重新取得有效执行权，旧权限不能写回或启动动作。
2. **Given** 原节点离线、drain或禁用，**When** 批准后调度，**Then** 等待原节点恢复合法条件并显示原因，不迁移另一节点、不重新检出重做。
3. **Given** 原工作区、封存文件或报告缺失/篡改，**When** 恢复复核，**Then** 安全失败且不发布、不重新生成证据假装等价，原封存证据仍可核对。
4. **Given** 审批等待时间较长，**When** 批准恢复，**Then** 等待时间不扣执行预算，既有剩余执行预算不增加；真正复核/继续执行耗时仍计入。
5. **Given** 两个合法领取者或丢领取响应，**When** 竞争恢复同一检查点，**Then** 至多一次有效后续执行，未确认领取不导致新进程接管或旧动作重放。

### User Story 4 - 条件、取消和发布不能绕过审批（Priority: P1）

条件和取消行为清楚，上传只消费与本次封存证据匹配的实际审批。

**Why this priority**：跳过审批不能自动得到发布授权，取消也不能被迟到批准复活。

**Independent Test**：含条件审批/上传的配置、挂起取消、重复审批和未知发布保护的实际负例。

**Acceptance Scenarios**：

1. **Given** 原冻结条件使approval跳过，**When** 后续upload仍生效，**Then** 因缺少这次实际批准阻止上传；若upload亦跳过则无发布动作，不虚构批准。
2. **Given** 已安全挂起或批准但尚未恢复执行，**When** 管理员取消，**Then** 事务确定取消且不启动用户post；迟到决定/领取不能复活。
3. **Given** 恢复已实际开始，**When** 取消与批准/领取竞争，**Then** 沿真实当前执行停止规则处理，只在物理停止证实后释放相应保护。
4. **Given** 同一流水线有多个审批或既有发布unknown，**When** 决定当前审批，**Then** 只作用于精确当前检查点，不替代其它审批，也不解除未知发布结果保护。

### User Story 5 - 本地调试需要明确交互（Priority: P1）

开发者本地运行构建时，在审批步骤看到安全说明并自行确认继续。

**Why this priority**：本地调试复用配置但不能默认批准或模拟远程审批身份。

**Independent Test**：真实终端批准/拒绝、无终端与取消，检查实际脚本次数和纯预览行为。

**Acceptance Scenarios**：

1. **Given** 本地无生效upload且交互终端可用，**When** 到达生效approval并明确确认，**Then** 只继续该次下一步骤，等待不扣执行预算；本地确认不成为远程发布授权。
2. **Given** 本地无交互终端、拒绝、输入结束或等待中取消，**When** 到达/等待approval，**Then** 不默认放行、不执行后续步骤或用户post，并保留准确失败/取消原因。
3. **Given** 生效upload或尚未实现的通知能力，**When** 本地实际运行，**Then** 在用户动作前明确拒绝；纯dry-run只安全预览，不读取材料、等待输入或请求远端。

### Edge Cases

- 控制端在检查点入库前后丢响应；Agent退出而原工作区仍在，损坏/未知本地证据不能猜恢复。
- 挂起、批准、取消、恢复领取竞争；节点凭据轮换、授权收窄、原节点删除与旧执行权回报。
- 前置报告缺失/失败、中央上传未确认、签名资源清理失败；post产生新文件不能修改原放行证据。
- 多审批旧请求迟到，拒绝后重发批准，等待期间项目改组/参数/方案/分支变化。
- approved后的产物变化、整个原工作区被替换、剩余预算恰好耗尽、原节点已无所需工具。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：沿原配置中的approval、冻结when与严格校验，不增新步骤类别或独立审批执行体系。
- **FR-002**：远程到生效审批时先验证并封存已完成产物、声明报告、进度及剩余预算；发布段前报告必须满足019真实规则。
- **FR-003**：仅在本次全部动作停止明确、必要日志/产物/检查点确认、临时签名资源清理成功后安全挂起；未知保原停止保护。
- **FR-004**：安全挂起释放节点和全局执行容量，同时保留项目同名build互斥、原节点/工作区归属。
- **FR-005**：挂起后不得持续授旧执行权或执行用户动作；重启不重新执行已完成步骤或签名操作。
- **FR-006**：待审批列表与原构建详情提供安全检查点、证据关联、当前状态和决定审计，table/JSON一致。
- **FR-007**：决定仅approver/admin；trigger及node身份不能决定，鉴权和状态检查与决定持久化必须一致。
- **FR-008**：批准/拒绝绑定精确当前审批，不以build ID的旧决定作用于后续另一次审批；意见可选、有界、安全保存。
- **FR-009**：记录决定身份、真实时间、意见、检查点与原证据；决定不可静默覆盖。
- **FR-010**：同审批同决定重复返回原结果；不同决定/不同意见/过时检查点拒绝，网络失败不自动改决定。
- **FR-011**：拒绝为cancelled/approval_rejected；不启动用户post、签名资源准备或后续发布，原证据保持。
- **FR-012**：批准后仅原节点恢复；节点未满足健康、授权、工具或容量条件时等待并明确原因，不迁移或重做。
- **FR-013**：恢复需新的合法执行权并验证精确检查点/当前身份，旧执行权拒所有写回和新动作。
- **FR-014**：同一构建号/原提交/定义/最终参数/条件与历史保持，恢复仅下一未执行步骤，已完成动作不得重跑。
- **FR-015**：恢复重新核对原工作区归属及封存文件/报告的实际内容，缺失或变化安全失败，不重建证据放行。
- **FR-016**：签名材料及发布授权恢复时重新校验当前明确条件；审批不代替当前节点、应用或商店授权。
- **FR-017**：排队/等待审批不计执行时间，挂起剩余普通/收尾预算不增长；恢复复核及真正执行仍按原累计预算。
- **FR-018**：恢复领取去重/竞争维持至多一次有效后续执行；未知领取保证据，不由新进程自动接管。
- **FR-019**：已安全挂起或批准但尚未恢复时取消可事务完成，不启动用户post；恢复已开始则沿当前真实停止规则。
- **FR-020**：取消、拒绝、批准及领取竞争有唯一一致结果，迟到决定/回报/领取不能复活终态。
- **FR-021**：条件跳过approval不是批准，仍生效upload必须因缺批准被阻止；两个均跳过不制造审批/发布。
- **FR-022**：多审批各有独立当前检查点与决定；后续不能消费另一审批或旧构建的放行。
- **FR-023**：审批检查点/原证据受保留保护，解除物理停止或批准不解除发布unknown保护。
- **FR-024**：节点有待审批或已批准待恢复构建时不能直接删除；drain/disable及轮换遵守当前权限规则。
- **FR-025**：本地生效approval仅交互终端明确确认可继续，等待不扣执行预算；无终端/拒绝/输入结束/取消不默认批准且不执行后续用户动作/post。
- **FR-026**：本地确认不是远程发布授权，生效upload仍在用户动作前拒绝；本地不创建控制端审批状态。
- **FR-027**：MVP通知默认false且不依赖通知交付；尚未实现的生效通知明确拒绝，不无声忽略；dry-run无交互/网络/秘密读取。
- **FR-028**：输入/查询/错误不公开参数、脚本正文、密钥、材料或节点私有路径；有界列表、意见与外部输入严格校验。
- **FR-029**：使用真实双数据库同suite、macOS/Linux原节点、多节点容量竞争、实际终端与控制端/Agent重启、旧权限及文件篡改验证；必要检查与Spec Kit收敛通过后整功能提交。
- **FR-030**：依赖已交付008/019/020及当前010/011发布消费者的完整实现和必要自动检查；真实商店/Apple材料与上传由用户人工验收，不阻塞审批完整代码。012/custom及全MVP最终Flutter联合验收保留，不反向形成提交依赖循环。

### Key Entities

- **审批检查点**：原构建/节点/步骤、实际完成进度、封存证据和剩余预算；与下一审批区分。
- **审批决定**：精确检查点、批准/拒绝、身份、时间与意见；不可冲突覆盖。
- **原节点恢复**：同一构建的下一合法执行，复核原工作区/证据及当前权限，保原历史与预算。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：一次有真实产物/报告的审批挂起后，另一命名构建实际执行且原同名构建不能竞争通过；停止/清理未知负例全部正确保持保护。
- **SC-002**：至少20个对精确同一审批的并发决定只形成一个有效决定，重复一致、冲突拒绝，无机密公开。
- **SC-003**：控制端与原节点分别重启至少一次，批准后所有原已完成动作次数保持，只有下一步骤实际执行一次。
- **SC-004**：等待时间超过原剩余执行预算后仍能合法恢复，真实剩余预算不增加；等待与执行耗时准确区分。
- **SC-005**：原节点离线/禁用/权限收窄、缺工作区/证据篡改、旧审批/旧权限、跳过审批与取消竞争负例全部阻止不合法发布。
- **SC-006**：真实终端批准/拒绝、无终端、输入结束、等待取消与dry-run行为全部符合要求；本地有效upload始终先拒绝。
- **SC-007**：两种现有持久后端运行相同用例，macOS/Linux实际节点与至少两个节点竞争/释放容量通过，检查点证据受保护且未知发布不被解除。
- **SC-008**：全部20AC与必要检查/收敛有真实证据；模拟审批、勾任务、交叉编译不代实际行为，完成后只有一次整功能本地提交。

## Assumptions

- 依据docs/plans/{PLAN,CONFIGURATION,INTERFACES,MULTI_NODE,MVP_EXECUTION,SPECKIT_ROADMAP}.md；原则2.1.0。
