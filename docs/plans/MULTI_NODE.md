# 多构建节点设计

本文件描述待实现的多 node 架构，是 [PLAN.md](PLAN.md) 的组成部分。
当前代码仅完成双 CLI 初始化，尚无控制端、Agent 或分布式执行能力。

## 拓扑与职责

```text
mybuilds 客户端 / Webhook
          │
          ▼
mybuilds-server 控制端（一个进程，Linux/macOS）
  ├─ 数据库：项目、构建号、节点、任务归属、审批、上传记录
  ├─ 调度：节点能力、项目允许节点、空闲容量、同项目串行
  └─ 中央存储：脱敏日志、已完成上传的产物
          ▲ HTTPS：领取任务、心跳、事件与文件回传
          │ Agent 主动发起连接
          ├─ mybuilds-agent：macOS 节点 A（iOS / Android）
          ├─ mybuilds-agent：macOS 节点 B（iOS / Android）
          └─ mybuilds-agent：Linux 节点 C（Android）
```

客户端用于触发、查询和审批；控制端不运行用户的构建 shell。
Agent 在节点上检出指定 SHA，复用本地 run 的流水线引擎。
同机部署也使用控制端与 Agent 两个进程；增加节点时沿用同一协议。
一期不引入消息队列、共享文件系统或 Kubernetes，不实现多控制端高可用。
这种控制端与执行节点分工参考 [Jenkins 节点模型](https://www.jenkins.io/doc/book/managing/nodes/)，
具体协议采用本项目的标准库 HTTPS 和数据库队列。

## 节点与任务分配

- 管理员创建节点并获取一次性显示的独立 token；控制端只保存摘要，支持撤销和更换。
  Agent 无用户/admin 权限，只能操作分配给自己的任务；节点端接口从 token 推导身份。
- 节点保存名称、OS/架构、工具能力、管理员标签、容量和最后心跳。
  自报工具检测结果用于诊断，不能自行取得受保护的发布标签或项目授权。
- 流水线 `runner` 声明 `platform: android|ios` 和 `labels` 字符串列表；管理员另设项目允许的节点集合。
  调度取平台、标签、项目授权与健康空闲节点的交集；无匹配节点时排队并显示原因，不退回任意节点。
  未声明 runner 时，仅在项目指定的默认节点上执行；项目也未指定时拒绝远程触发。
- 同项目跨所有节点保持串行；默认每节点容量为 1，全局上限默认 1，扩容时显式提高。
  iOS 须匹配 macOS、Xcode 与所需签名资源；Android 可匹配 Linux 或 macOS。
- 任务领取在数据库事务中校验并发、项目互斥与状态，生成唯一 attempt、lease_id、递增 lease_epoch 和过期时间。
  排队任务才可选择任意合格节点；一旦开始，整条流水线固定该节点，不做逐步骤迁移。

配置示意（待实现）：

```yaml
runner:
  platform: ios
  labels: [xcode, ios-signing]
```

## 通信、租约与故障

- Agent 主动通过 HTTPS 领取任务与续租，无需开放入站端口；跨主机必须校验证书。
  建议心跳间隔 5s、租约 30s，均可配置；正式协议在 007 的 plan/contracts 中确定。
- 续租成功后 Agent 用本机单调计时估算保守执行期限；期限前未获得续租，停止接新步骤，
  TERM/KILL 本次构建进程组并清理签名资源。重连不能沿用过期执行权。
- 心跳、日志、步骤状态、文件上传、发布意图和最终结果均携带任务/attempt/租约标识。
  控制端条件更新拒绝过期租约、错误节点和重复终态；事件序号处理重发，不能仅凭 build_id 更新。
- 控制端重启后读取持久化租约并与节点核对，不能因为控制端重启就判所有构建中断。
  节点租约过期后任务标为 interrupted；原节点停止证据不足时保留执行结果不确定的提示。
- 已开始的任务失联不自动交给另一节点重跑。用户显式 retry 使用新构建号/attempt 和原 SHA、配置、参数；
  发布结果未知时仍须先确认。租约不能撤销已发往外部的请求，不能保证外部动作恰好一次。
- 取消先持久化 cancel_requested，节点续租/轮询时取得意图并终止本次进程组。
  收到停止确认才展示已取消；节点失联时显示取消待确认，租约过期按中断处理，并保留外部副作用未知状态。
- 节点 drain 停止领取新任务，已有执行继续并保持续租；待审批任务恢复须等节点重新 enable。
  节点离线、禁用和删除的处理需测试。
  禁用先撤销执行授权并等待停止或过期；有活动或待审批构建的节点不得直接删除。

## 审批、日志、产物与密钥

- 到 approval 前，Agent 将产物和必要脱敏记录完整回传控制端；确认入库后保存执行位置，释放节点和全局容量。
  保留节点工作区、项目串行约束与节点归属；批准后在原节点以新租约恢复。
  节点离线则等待并提示，工作区缺失则失败；一期不把批准后的任务迁移到另一节点。
- 日志先脱敏再传输，按步骤/偏移去重；本地保留未确认的缓冲，控制端提供 SSE 与历史查询。
  限制缓冲与请求大小；不可无声丢弃日志，背压或缓冲耗尽时记录失败并停止任务。
- 产物用 HTTPS 回传控制端，临时文件写完后校验大小与 SHA-256 并原子发布；请求不能指定任意服务端路径。
  重发按产物标识幂等，节点失联时已确认产物仍可下载；待审批与未知上传结果的产物受 retention 保护。
- 构建 SHA 在控制端确定，流水线配置快照在首次执行前落库并校验绑定该 SHA，重试从快照恢复。
  控制端持有解析 SHA/轮询所需 Git 只读凭据，节点另有本地检出凭据与签名资源；执行/上传密钥按引用从该节点的受限 secrets 文件解析。
  中央通知密钥仅在控制端使用；租约响应不下发管理员 token 或完整控制端环境。
- 上传前由控制端持久化意图并授权当前租约执行；通知由控制端根据已持久化事件发送。
  若节点已发送但回报未被确认，标为结果未知，不自动重发。通知失败不覆盖构建结果。

## 存储与实施

控制端独占 SQLite 或 PostgreSQL；多个 Agent 通过 API 访问，不共享 SQLite 文件，也不直接访问数据库。
控制端 `~/.mybuilds` 保存数据库、日志与中央产物；节点独立 data_dir 保存工作区、日志缓冲和临时资源。
增加 PostgreSQL 不等于多控制端高可用；执行实例归属和服务互斥需要另行设计。

按路线先完成 006 控制端与持久化队列，再完成 007 Agent 多节点闭环，随后 008 重启恢复。

取消与断网停止、日志重发和产物回传；008/010/013 分别扩展恢复、审批与发布的故障验收。
